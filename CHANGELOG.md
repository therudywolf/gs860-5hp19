# Changelog

## 2026-09-25: AGS separated from the TCC lockup, program-to-matrix mapping, turbine monitor, docs corrected from the code

**EN**

- **AGS vs lockup.** What docs 01, 03, 05, 06, 08, 09 and the glossary called the TCC lockup (the "four-stage ladder" `0x888C`, the value `0xFFFF9216`, the tables `0x901E-0x915E`, `0x88B0`, `0x88C0`, `0x819C / 0x819D`, `0x8214`) is AGS, the adaptive program selection: its points choose the shift program and never reach an output (found 23.09.2026). Doc 03 is rewritten around the real lockup: request 0 / 1 / 2 from `0x29056` into `0xFFFF91F9`, thresholds `0x993A` with the groups `0x897E` and the gear mask `0x8978`, the clutch state machine 0-8 (`0x32B08`, `0x33F66`), PWM `0xFFFF95BA` up to 0x1F40, hold after a shift `0xB139-0xB13C`, closing slope `0xB0FC`, release below 950 engine rpm, ATF limits `0x320DC`. The AGS material moved to doc 03 §7 "AGS: adaptive program selection (not the lockup)".
- **Programs and matrices.** The active program is `0xFFFF91A0`, `0xFFFF91B0` is the forced program. The matrix comes from the table in `0x24BA4`: D = matrices 14 / 06, S = 11 / 15, M = 10 (08 with hot ATF), 09 = P8, 00 / 01 / 02 = the `0xFFFF90CD` steps (hill steps: hypothesis). S flag `0xFFFF91CB`, M flag `0xFFFF91F3`. Docs 01, 02, 06, glossary.
- **Turbine monitor.** The cause of limp mode at the rev limiter: `0x26C84` sets fault 0x25 when the turbine `0xFFFF8DE2` stays at or above [`0x8B44`] = 6720 for about a second. Limp flag `0xFFFF90C1` = status frame 0B 03 byte 18 bit 0. `0xFFFF9113` is the kickdown flag, not limp mode. Docs 05 §6, 09, 10.
- **Manual mode.** The minimum-gear table `0x8AE2` + 5 × program is the over-rev protection on manual downshifts. An upshift threshold at the fuel cut (58 / 106 / 151 / 212) is not overrun protection: with the converter locked it upshifts on the limiter plateau and lies above the 6720 monitor threshold. Docs 02 §5, 05, 09.
- **Shift records.** f24 is at `0xDEC4 / 0xDEC9 / 0xDECE / 0xDED3` (slip-pressure ceiling), phase 4 ends on the f27 timer only, f43 is the phase-9 duration, the 10 ms unit of f45 is proven, record selection `0x34220`, `0xFFFF9595` is the target gear and `0xFFFF9716` the gear being left (the labels were swapped), `0xFFFF97A0` is turbine torque. Doc 04 §14.
- **CAN.** Target gear in EGS1 byte 0 bits 0-2 from the start of the shift, torque reduction through one channel, EGS1 byte 3, brake DME2 byte 6 bit 0 read as `0xFFFF97F5`, DME2 byte 2 not read by the stock software. The `0xAB0C…` maps are the reference slip of the TCC regulator, not torque reduction. Doc 04 §9, §15.
- **Kind-2 records, checked in code.** `0xDD12` is only the 1 to 6 transition, `0xDD18` only 2 to 6 (the manual 2-1 in M, P6, P8, P9: gear code 6 is 1st with one extra shift element, not neutral), `0xDD24` serves the 2-1 in D and S and every 3-2. The f41 axis is turbine / 32 (`0xFFFF97E2`). The note of 24.09 (0xDD12 = 2-1, 0xDD18 = 3-2, axis n_out / 32) was wrong (doc 04 §2, §6, glossary).
- **Disputed, not yet checked in code**, both readings given: the filter input `0xFFFF8DA6` or `0xFFFF8DA8` (doc 02 §3), what `0x8EEA` is compared with (doc 05 §1).
- **XDF v3, generated.** `xdf/*.xdf` are now generated from `catalog/gs8600_19d0.json` by `tools/make_xdf.py` and are no longer edited by hand. Roles corrected as above (AGS tables in their own category, `0x993A` lockup thresholds, `0xAB0C…` reference slip, matrix titles by index k with the program that uses each), 32 new entries (turbine monitor `0x8B44`, minimum gear `0x8AE2`, lockup groups `0x897E`, gear mask `0x8978`, hysteresis `0x8B4C`, open delay `0x8ED8`, lower-level lockup cells `0xB0D4`-`0xB140`, `0xB0E2`, f24 and f27 of loaded upshifts, AGS bounds `0x8878`-`0x887D`, error masks `0x8366`, `0x8B32`, lever filter `0x8E86`, output-speed filter weights `0x8F72`/`0x8F73`). **TunerPro categories were off by one in v2.1** (0-based numbers in CATEGORYMEM, TunerPro counts from 1, the 16 matrices had no category), fixed. All 870 old entries keep their addresses and shapes.
- **Presets.** Doc 08 §6 has a note per preset: which edits change AGS instead of the lockup, which matrices S / M / D really use, the over-rev and limp risk of the manual thresholds. The recipe files are unchanged and will be revised separately.

**RU**

- **AGS и блокировка ГДТ.** То, что документы 01, 03, 05, 06, 08, 09 и глоссарий называли блокировкой ГДТ («лесенка из четырёх ступеней» `0x888C`, величина `0xFFFF9216`, таблицы `0x901E-0x915E`, `0x88B0`, `0x88C0`, `0x819C / 0x819D`, `0x8214`), это AGS, адаптивный выбор программы: его очки выбирают программу переключения и в выходы не идут (найдено 23.09.2026). Документ 03 переписан вокруг настоящей блокировки: запрос 0 / 1 / 2 из `0x29056` в `0xFFFF91F9`, пороги `0x993A` с группами `0x897E` и маской передач `0x8978`, автомат муфты 0-8 (`0x32B08`, `0x33F66`), ШИМ `0xFFFF95BA` до 0x1F40, удержание после переключения `0xB139-0xB13C`, наклон замыкания `0xB0FC`, размыкание ниже 950 об/мин ДВС, пределы по ATF `0x320DC`. Материал про AGS перенесён в документ 03 §7 «AGS: адаптивный выбор программы (не ГДТ)».
- **Программы и матрицы.** Активная программа это `0xFFFF91A0`, `0xFFFF91B0` это принудительная программа. Матрицу выбирает таблица в `0x24BA4`: D = матрицы 14 / 06, S = 11 / 15, M = 10 (08 при перегреве ATF), 09 = P8, 00 / 01 / 02 = ступени `0xFFFF90CD` (горные: гипотеза). Признак S `0xFFFF91CB`, признак M `0xFFFF91F3`. Документы 01, 02, 06, глоссарий.
- **Монитор турбины.** Причина аварийного режима на отсечке: `0x26C84` ставит ошибку 0x25, когда турбина `0xFFFF8DE2` около секунды не ниже [`0x8B44`] = 6720. Признак аварийного режима `0xFFFF90C1` = кадр 0B 03 байт 18 бит 0. `0xFFFF9113` это признак кикдауна, а не аварийного режима. Документы 05 §6, 09, 10.
- **Ручной режим.** Защиту от перекрута при ручном понижении даёт таблица минимальной передачи `0x8AE2` + 5 × программа. Порог вверх у топливной отсечки (58 / 106 / 151 / 212) не защита на накате: при замкнутой ГДТ он даёт самоповышение на полке отсечки и лежит выше порога монитора 6720. Документы 02 §5, 05, 09.
- **Записи переключения.** f24 лежит в `0xDEC4 / 0xDEC9 / 0xDECE / 0xDED3` (потолок давления скольжения), фаза 4 кончается только по таймеру f27, f43 это длительность фазы 9, единица 10 мс у f45 доказана, выбор записи `0x34220`, `0xFFFF9595` это целевая передача, а `0xFFFF9716` передача «из» (подписи были перепутаны), `0xFFFF97A0` это момент турбины. Документ 04 §14.
- **CAN.** Целевая передача в EGS1 байт 0 биты 0-2 с начала переключения, снятие момента одним каналом, EGS1 байт 3, тормоз DME2 байт 6 бит 0 читается как `0xFFFF97F5`, байт 2 DME2 штатное ПО не читает. Карты `0xAB0C…` это опорное скольжение регулятора ГДТ, а не снятие момента. Документ 04 §9, §15.
- **Записи вида 2, проверено кодом.** `0xDD12` это только переход 1 в 6, `0xDD18` только 2 в 6 (ручное 2-1 в M, P6, P8, P9: код передачи 6 это 1-я с дополнительным элементом, не нейтраль), `0xDD24` обслуживает 2-1 в D и S и каждое 3-2. Ось f41 это турбина / 32 (`0xFFFF97E2`). Запись 24.09 (0xDD12 = 2-1, 0xDD18 = 3-2, ось n_вых / 32) была неверной (документ 04 §2, §6, глоссарий).
- **Спорно, кодом ещё не проверено**, приведены оба прочтения: вход фильтра `0xFFFF8DA6` или `0xFFFF8DA8` (документ 02 §3), с чем сравнивается `0x8EEA` (документ 05 §1).
- **XDF v3, генерируется.** `xdf/*.xdf` теперь собираются из `catalog/gs8600_19d0.json` скриптом `tools/make_xdf.py` и руками больше не правятся. Роли исправлены как выше (таблицы AGS в своей категории, пороги блокировки `0x993A`, опорное скольжение `0xAB0C…`, названия матриц по индексу k с программой, которая её берёт), 32 новые записи (монитор турбины `0x8B44`, минимальная передача `0x8AE2`, группы блокировки `0x897E`, маска передач `0x8978`, гистерезис `0x8B4C`, выдержка размыкания `0x8ED8`, ячейки нижнего уровня ГДТ `0xB0D4`-`0xB140`, `0xB0E2`, f24 и f27 повышений под нагрузкой, границы очков AGS `0x8878`-`0x887D`, маски ошибок `0x8366`, `0x8B32`, фильтр рычага `0x8E86`, веса фильтра выходного вала `0x8F72`/`0x8F73`). **Категории TunerPro в v2.1 съезжали на одну** (номера с 0 в CATEGORYMEM, TunerPro считает с 1, у 16 матриц категории не было), исправлено. Все 870 прежних записей сохранили адреса и форму.
- **Пресеты.** В документе 08 §6 по каждому пресету: какие правки меняют AGS, а не блокировку, какие матрицы на деле работают в S / M / D, риск перекрута и аварийного режима от ручных порогов. Файлы рецептов не менялись и будут пересмотрены отдельно.

## 2026-09-23: checksums found, shift-matrix unit corrected, presets recomputed

**EN**

- **Checksums.** The handler of DS2 command `0x0A` (`0x1360`) computes three CRC-16/XMODEM sums with the routine `0x221C` and the table at `0x3EDA`: loader `0x0–0x42FF` at `0x5FFE`, program `0x10000–0x3F77B` at `0x3F7FE`, calibration `0x8000–0xFFCD` at `0xFFFE`. Stock and factory Alpina match on all three. The routine has no other caller, so the ECU checks the sums only when a tester asks: that is why edited calibrations with a stale sum drove. New `tools/gs860_crc.py` (`check` and `fix`, full 256K and 512K images, 32K partials). `apply_recipe.py` checks the loader and program sums of the input and recomputes the calibration sum after writing, `make_recipe.py` leaves `0xFFFE–0xFFFF` out, `egs_tables.py info` prints the sums. Docs 01, 07 §6, 09 rewritten ("do not touch the tail" becomes "the tools recompute the sum").
- **Shift-matrix unit.** The shift matrices and the TCC speed axes hold **output shaft rpm / 32**, not km/h: the decision compares the value with `0xFFFF918F`, written at `0x24F60` as the filtered output shaft rpm shifted right by 5 (doc 02 §3). On the reference car one unit is 1.18 km/h, so every rpm derived from the old km/h reading was 18 % low. Shift rpm does not depend on the final drive or tyres. Docs 02 and 03 rewritten, 06, 08, 10 §7 and the glossary corrected, XDF v2.1 (units and descriptions).
- **Presets recomputed.** With the real unit the 16.09 sport shift points (`66 / 120 / 171` from 63 % pedal) meant 7740 / 7676 / 7699 turbine rpm: never reached under load, the box hung at the limiter in S. The manual programs had `255` in the upshift columns (no overrun protection) and a kickdown landing at 6909…6944 rpm, above the spark cut. New `egs_tables.py verify-shift` checks the 16 matrices against doc 02 §4, `--fix` lowers only the cells that break the rules. v18, v19 and v20 were rebuilt with `verify-shift --spark 6656 --cut 6784 --fix`: sport upshifts at most 47 / 94 / 136 (turbine 5512 / 6013 / 6123 rpm at the command), manual upshift 58 / 106 / 151 / 212 (overrun protection at the fuel cut), every downshift landing at most 6150 rpm. Hydraulics and TCC unchanged. Schema `gs860-recipe/2`, the 16.09 result hashes are kept in each recipe under `history`. Not road-tested yet.
- `tests/test_tools.py`: runs without images. With `GS860_STOCK` it applies every recipe, checks the sums, the reference hashes, the shift rules and a make_recipe round trip.

**RU**

- **Контрольные суммы.** Обработчик команды DS2 `0x0A` (`0x1360`) считает три суммы CRC-16/XMODEM функцией `0x221C` по таблице `0x3EDA`: загрузчик `0x0–0x42FF` в `0x5FFE`, программа `0x10000–0x3F77B` в `0x3F7FE`, калибровка `0x8000–0xFFCD` в `0xFFFE`. Сток и заводская Alpina сходятся по всем трём. Других вызовов у функции нет, значит, блок проверяет суммы только по запросу тестера: поэтому правленые калибровки со старой суммой ездили. Новый `tools/gs860_crc.py` (`check` и `fix`, полные образы 256K и 512K, партиалы 32K). `apply_recipe.py` проверяет суммы загрузчика и программы на входе и пересчитывает сумму калибровки после записи, `make_recipe.py` не берёт в рецепт `0xFFFE–0xFFFF`, `egs_tables.py info` печатает суммы. Документы 01, 07 §6, 09 переписаны («хвост не трогать» стало «сумму пересчитывают инструменты»).
- **Единица матриц переключения.** Матрицы переключения и оси скорости таблиц ГДТ хранят **обороты выходного вала / 32**, а не км/ч: решение сравнивает значение с `0xFFFF918F`, который пишется в `0x24F60` как отфильтрованные обороты выходного вала, сдвинутые вправо на 5 (документ 02 §3). На референсной машине единица равна 1.18 км/ч, поэтому все обороты по старому прочтению занижены на 18 %. Обороты переключения не зависят от главной пары и колёс. Документы 02 и 03 переписаны, 06, 08, 10 §7 и глоссарий исправлены, XDF v2.1 (единицы и описания).
- **Пресеты пересчитаны.** В настоящих единицах точки спорта 16.09 (`66 / 120 / 171` с 63 % педали) означали 7740 / 7676 / 7699 об/мин турбины: под нагрузкой недостижимо, в S коробка висела в отсечке. У ручных программ в столбцах вверх стояло `255` (без защиты на накате), а кикдаун приводил мотор на 6909…6944 об/мин, выше искры. Новая команда `egs_tables.py verify-shift` проверяет 16 матриц по правилам документа 02 §4, `--fix` опускает только нарушающие ячейки. v18, v19 и v20 пересобраны командой `verify-shift --spark 6656 --cut 6784 --fix`: спорт вверх не выше 47 / 94 / 136 (5512 / 6013 / 6123 об/мин турбины в момент команды), ручные вверх 58 / 106 / 151 / 212 (защита на накате на топливной отсечке), после любого понижения не выше 6150 об/мин. Гидравлика и ГДТ не менялись. Схема `gs860-recipe/2`, хэши результата от 16.09 сохранены в каждом рецепте в поле `history`. На машине ещё не проверено.
- `tests/test_tools.py`: работает без образов. С `GS860_STOCK` применяет каждый рецепт и проверяет суммы, эталонные хэши, правила точек и обратную сборку make_recipe.

## 2026-09-16 — preset v17 → v18 (fix)

**EN.** The v17 preset raised `0x8EEA` from 7000 to 7300 as a "turbine over-speed limit". Disassembly of the write sites (0x20D78: `ADC × 25250 / 1024` → `0xFFFF906C/906E`) proves the function 0x265F4 is a supply-voltage monitor (7.0 / 9.0 V thresholds, 1.5 V channel spread), so the change had moved a 7.0 V threshold to 7.3 V. v18 = v17 with `0x8EEA` back at stock; the recipe `wolf4x_v18_sport_daily.json` replaces the v17 recipe (SHA-256 of the result `0bfd1d0d10037e020bcbfb16fdf5941bf17d0ec085dd5dd0cdec22c65419812e`). Docs 05, 08, 09, 10 and the XDF constant titles updated.

**RU.** В пресете v17 `0x8EEA` был поднят с 7000 до 7300 как «порог разноса турбины». Дизассемблер записей переменных (0x20D78: `АЦП × 25250 / 1024` → `0xFFFF906C/906E`) доказывает, что функция 0x265F4 — монитор напряжения питания (пороги 7.0 / 9.0 В, разбег каналов 1.5 В), то есть правка сдвигала порог 7.0 В на 7.3 В. v18 = v17 с `0x8EEA`, возвращённым к стоку; рецепт `wolf4x_v18_sport_daily.json` заменяет рецепт v17 (SHA-256 результата `0bfd1d0d10037e020bcbfb16fdf5941bf17d0ec085dd5dd0cdec22c65419812e`). Обновлены документы 05, 08, 09, 10 и заголовки констант в XDF.

**EN**

- XDF v2 for the full 256K image and the 32K partial (850 tables and 20 constants; shift-execution tables named by record set / field / transition after the 16.09 reverse).

- Recipe `wolf4x_v18_sport_daily.json` — full diff of the v18 preset against stock; verified byte-exact round trip (SHA-256 `0bfd1d0d…`).
- Corrections relative to earlier project notes (refuted):
  - `0x81A0 / 0x81B2` are not "shift phases / solenoid phases" but a gear-selection module threshold vs engine rpm/32;
  - the `B73E / B7A4 / B90E / …` family (kind3 f45) is off-going clutch pressure on load downshifts, not "fill time"; real fill time is the 1D curves `D6C2 / D722 / D782 / D7E2` (kind1 f10);
  - `0x8F00 / 0x8F08 / 0x8F0A / 0x8EFC` and `0xFFFF906C / 906E` are voltages in mV, not TCC temperatures;
  - `0x265F4` with `0x8EE8 / 0x8EEA / 0x8EF0` (9000 / 7000 / 1500) compares the same voltage variables (written at 0x20D78 as ADC × 25250 / 1024) — the "turbine 7000 rpm protection" reading is refuted; the cause of limp mode at the rev limiter is an open question;
  - `0xAB0C…0xAE40` are torque-reduction request maps, not TCC slip maps; `0xA066…0xA20A` are not TCC thresholds;
  - "the table zone tiles with no remainder" — wrong; 536 tables cover 15,284 of the zone's bytes, the rest are scalars, matrices and short curves.
