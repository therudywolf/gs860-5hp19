# 03 · Блокировка гидротрансформатора (WÜK / TCC)

> **Переписано 25.09.2026.** До этого документ описывал как блокировку ГДТ «лесенку из четырёх ступеней» (0x1DEBC, 0x888C, `0xFFFF9216`, таблицы 0x901E-0x915E). 23.09.2026 разбор кода показал, что это AGS, адаптивный выбор программы: его очки выбирают программу переключения и до муфты не доходят. Этот материал с исправленными названиями перенесён в §7. Настоящая блокировка описана в §1-§4.

## 1. Главное

- Блокировку ведут два уровня. Верхний: функция 0x29056 раз в 10 мс считает запрос `0xFFFF91F9`: 0 = разомкнута, 1 = регулируемое скольжение, 2 = замкнута. Нижний: автомат муфты 0x32B08 (состояние `0xFFFF9632`, 0-8) и задача 0x33F66 ведут ШИМ `0xFFFF95BA` от 0 до 0x1F40 (8000, полная шкала). Цепочка целиком: 0x29056, таблица 0x993A с группами 0x897E, запрос `0xFFFF91F9`, автомат состояний, регулятор, ШИМ `0xFFFF95BA`, выход `0xFFFFFF34`.
- Смысл запроса 0 / 1 / 2 выведен из таблиц нижнего автомата и выхода ШИМ: запрос 0 сводится к состоянию 1 (ШИМ 0), запрос 1 к состоянию 4 (регулируемое скольжение), запрос 2 к состоянию 7 (ШИМ 0x1F40). Документации Bosch нет.
- Пороги заданы в **n_вых / 32** (`0xFFFF918F`, та же переменная, что в матрицах переключения, документ 02 §3), по оси педали коробки `0xFFFF9182`. Набор порогов (группа) зависит от программы и передачи. В 1-й передаче блокировки нет: маска передач 0x8978 = 0x3C (2-5-я).
- Температура ATF участвует. Нижний уровень (0x320DC) до сырого 70 (около 22 °C) держит муфту разомкнутой, выше сырого 160 (около 110 °C) запрос скольжения работает как «разомкнуть», полное замыкание разрешено. При перегреве ATF (`0xFFFF90E4`) включаются программы PC и PD со своими группами порогов (§3).
- Отдельного «лимита блокировки по скорости» в верхнем уровне нет: муфта размыкается только при падении n_вых ниже порогов (§2).
- Проверено разбором кода 23-24.09.2026, вторым независимым разбором и исполнением кода нижнего уровня в эмуляторе. Где роль взята из стороннего реверса, это сказано в тексте.

## 2. Код: верхний уровень (запрос 0 / 1 / 2)

| Адрес | Что |
|---|---|
| `0x29056` | раз в 10 мс считает запрос `0xFFFF91F9` (функция 0x29056-0x29208) |
| `0x290A0` | группа порогов: байт `[0x897E + 4 × программа + передача - 2]`, программа из `0xFFFF91A0` (в коде база 0x897A + 4 + индекс) |
| `0x290D0` | `movea.l #$9B80`: указатель на таблицу порогов 0x993A |
| `0x290FC` | `cmp.b $FFFF918F`: сравнение порога с n_вых / 32 |
| `0x2912E` | прямой переход из 0 в 2 в первые ~20 с после включения блока |
| `0x291D4` | `move.b $8B4C`: гистерезис |
| `0x32B08`, `0x33F66` | нижний уровень (§4) |

Условия: передача `0xFFFF91AF` должна быть в маске 0x8978 = 0x3C (2-5-я), бит 8 слова ошибок `0xFFFF8FA2` выключает блокировку (документ 05 §6). Группа 0 значит «блокировки нет».

Переходы запроса (порог0 / порог1 / порог2 берутся из группы, §3):

- из 0 в 1: n_вых > порог1 и `0xFFFF9213` = 0,
- из 1 в 2: n_вых > порог2,
- из 2 в 1: n_вых < порог2 - [0x8B4C],
- из 1 в 0: n_вых < порог0 дольше [0x8ED7 + передача] тактов.

Сток: 0x8B4C = 3 (единицы n_вых / 32), выдержка [0x8ED7 + передача] = 6 тактов. Первые ~20 с после включения блока скольжение запрещено (`0xFFFF9213`, 0x15F78), в это время возможен прямой переход из 0 в 2 (0x2912E). Других ссылок на 0x993A, 0x9B80, 0x897E, 0x8978 в образе нет.

## 3. Таблицы порогов 0x993A и группы 0x897E

Таблица 0x993A (указатель 0x9B80), 2D8 30 × 7: `[u16 30][u16 7]`, ось X 30 байт (номер порога 0…29), ось Y 7 байт (педаль коробки `0xFFFF9182`, сток 0 / 5 / 46 / 59 / 72 / 97 / 122), данные 210 байт с 0x9963, строки по 30 байт. Группа g берёт столбцы 3g-3 (порог0, «размыкание ниже»), 3g-2 (порог1, «скольжение выше») и 3g-1 (порог2, «замкнута выше»). Значения в n_вых / 32, обороты турбины на пороге = значение × 32 × i (2-5-я: 1.999 / 1.407 / 1.000 / 0.742).

Группа = байт `[0x897E + 4 × программа + передача - 2]`, 16 программ × 4 байта (передачи 2-5). Завод:

| Программа | Группы для 2-й / 3-й / 4-й / 5-й |
|---|---|
| P0, P1 (D), P2, P3 (S) | 4 / 1 / 2 / 3 |
| PB (M) | 0 / 8 / 9 / 9 |
| PD (M при перегреве ATF) | 0 / 7 / 6 / 0 |
| PC (D при перегреве ATF) | 0 / 0 / 0 / 0, блокировки нет |
| P4-P6, PA, PE, PF | заводские значения здесь не приводятся |

В заводе используются группы 0-4 и 6-9, группы 5 и 10 свободны, группы 6-9 есть только у PB и PD.

Заводские пороги в оборотах турбины (порог0 / порог1 / порог2):

| Передача | D и S, малая педаль | D и S, педаль от 122 | M (PB) |
|---|---|---|---|
| 2 | 3966 / 4542 / 5757 | 3966 / 4542 / 5757 | блокировки нет |
| 3 | 900 / 990 / 4052 | 2791 / 3196 / 4052 | 2611 / 3016 / 4592, в пол 3466 / 3737 / 4592 |
| 4 | 960 / 1152 / 2880 | 1984 / 2272 / 2880 | 1984 / 2176 / 3584 |
| 5 | 1187 / 1234 / 1543 | 1686 / 1923 / 2137 | 1472 / 1615 / 2659 |

D и S пользуются одними группами (4 / 1 / 2 / 3), пороги растут с педалью. В D в пол заводские группы замыкают ГДТ во 2-й с 5757 и в 3-й с 4052 об/мин турбины: у отсечки мотор равен турбине. В M (PB) муфта замыкается в 3-й, 4-й и 5-й с 4592 / 3584 / 2659 об/мин турбины. Это важно для ручных порогов вверх (документ 02 §5).

Замер на референсной машине (лог под тягой, дроссель больше 5°): D, 1-3-я на 17-46 км/ч, скольжение 160…736 об/мин, ни одного замкнутого кадра. D, 4-я на 48-65 км/ч, скольжение до 704 об/мин. S, 4-я, замкнута в 100 % кадров. Отсюда нагрев ATF в городе. До 23.09.2026 этот замер объяснялся «лесенкой» (§7), на деле муфту ведут пороги 0x993A и нижний уровень (§4).

## 4. Нижний уровень: автомат муфты, ШИМ и защиты

Автомат 0x32B08 (таблицы 0x12EEC-0x12F9B), состояние `0xFFFF9632`:

| Состояние | Что |
|---|---|
| 0 | сброс, ШИМ 0 |
| 1 | разомкнута |
| 2, 3 | начало включения |
| 4 | регулируемое скольжение |
| 5 | роль в разборе не названа |
| 6 | замыкание, ШИМ растёт |
| 7 | замкнута: обработчик 0x33DE4 ставит ШИМ 0x1F40 (максимум) |
| 8 | выход из замыкания |

Путь вверх 1, 2, 3, 4, 6, 7, обратно через 8 и 5. Запрос 0 сводится к состоянию 1 (ШИМ `0xFFFF95BA` = 0), запрос 1 к состоянию 4, запрос 2 к состоянию 7. Проверено исполнением кода в эмуляторе.

- **Разрешение полного замыкания** `0xFFFF9634` (0x32150, по передаче, скорости и нагрузке). От него зависит вход в состояние 7, по нему выбирается запись 95FA. Без него муфта остаётся в скольжении (таблица 0x12F08). Есть ещё минимальное время скольжения `0xFFFF9655`. Условия 0x32150 разобраны не до конца.
- **Замыкание** (состояние 6, 0x33D32). ШИМ растёт с шагом [0xB0FC] × 100 в секунду при полной шкале 8000 (интегратор 0x2C684, шаг читает 0x33DB0, рост считает 0x3237A). Муфта считается замкнутой, когда скольжение меньше [0xB0D4] об/мин держится [0xB12E] × 10 мс или ШИМ дошёл до 8000. Минимальное время скольжения перед замыканием 0xB140 = 30 мс. Сток: 0xB0FC = 10 (1000 единиц ШИМ в секунду), 0xB0D4 = 10 об/мин, 0xB12E = 20 (0.2 с).
- **Фаза переключения для ГДТ** `0xFFFF964B` (0x32270): 2 = новая команда передачи, 3 = ожидание, 4 = переключение идёт (флаг `0xFFFF9718`), 5 = после флага `0xFFFF9730` и до снятия 9718, затем 1. Флаг 9730 ставится при синхронизации (0x3487A). В фазах 3 и 4 замкнутая муфта уходит в регулируемое скольжение (состояния 7, 8, 4, таблица 0x12F24). Тип переключения для ГДТ `0xFFFF9650` берётся из таблицы 0x12FAA по паре (текущая, целевая): 1 = повышение на одну, 2 = понижение на одну, 3 = понижение через одну (3-1, 4-2, 5-3).
- **Удержание после переключения.** В фазе 5 функция 0x32A38 (вызов из 0x32B48) не пускает автомат из скольжения в замыкание (из 4 в 6) и из открытой в начало включения (из 1 в 2), пока счётчик `0xFFFF9658` (шаг 10 мс, сброс вне фазы 5) меньше порога. Порог выбирается по типу переключения через указатель `0xFFFF962E` (массив 0x3B0B4, записи 0x3B026 / 0x3B032 / 0x3B03E): после повышения 0xB13B, 0xB139, после понижений 0xB13C, 0xB13A. Сток: 0xB139 = 100, 0xB13A = 20, 0xB13B = 100, 0xB13C = 20 (× 10 мс: 1.00 с после повышения, 0.20 с после понижения). Удержание идёт уже после смены передаточного числа. Ячейки общие для D, S и M.
- **Описатель 0x3B0C2.** На него указывают оба набора данных (массив 0x3B1F2), и все ячейки нижнего уровня читаются только через него: +0x08 массив записей типов 0x3B0B4, +0x58 0xB0FC, +0x6C порог 950, +0x78 0xB0D4, +0x98 0xB12E. Правка этих ячеек меняет D, S и M сразу.
- **Сброс по тормозу и оборотам мотора.** 0x33F66 (раз в 10 мс) вызывает в 0x33F74 проверку 0x33024. Сброс, если состояние `0xFFFF9632` не 0 и не 1, обороты мотора `0xFFFF97B0` ниже [описатель 0x3B0C2 + 0x6C] = 950, `0xFFFF97F5` = 1 (тормоз, кадр DME2 байт 6 бит 0) и `0xFFFF9634` = 0. Условия совместные: одно нажатие тормоза муфту не размыкает. Сброс идёт путём 0x33F9C: 9632 = 0, 9635 = 1, 95D0 = 0, 963E = 0 (ШИМ 0 в том же такте, затем состояние 1).
- **Обороты мотора.** По разбору нижнего уровня от 23.09.2026 при оборотах ДВС не выше 950 муфта принудительно размыкается и снова разрешается с 1200 (0xB0E2 = 1200, 0xAAC6 = 250). Обороты мотора коробка берёт из кадра DME1 (`0xFFFF8DB2`).
- **ATF** (0x320DC): до сырого 70 (около 22 °C) муфта всегда разомкнута, выше сырого 160 (около 110 °C) запрос скольжения работает как «разомкнуть», полное замыкание разрешено. Пересчёт сырых значений в °C приблизительный.
- **Мощность скольжения** контролирует 0x32986 (защита нижнего уровня).
- **Опорное скольжение регулятора** (`0xFFFF95A6`) задают шесть карт 8×8 в 0xAB0C-0xAEE3 (0xAB0C, 0xABB0, 0xAC54, 0xACF8, 0xAD9C, 0xAE40). Эта роль взята из стороннего реверса и принята 23.09.2026, собственного разбора кода этих карт в репозитории пока нет. Прежнее прочтение «карты снятия момента» (документ 04 §9) снято.
- **Выход.** Драйвер токов 0x2054C-0x205F4 обслуживает три канала (`вход × усиление[0xFFFF8CEE/8CF2] / период + смещение[0xFFFF8CF0/8CF4]`), регистры TPU `0xFFFFFF24 / 0xFFFFFF34` и CTM `0xFFFFF43C`. ШИМ муфты `0xFFFF95BA` уходит на выход `0xFFFFFF34`. Это тоже из стороннего реверса, принято 23.09.2026, часть цепочки (0x29056, 0x993A, 0x897E, `0xFFFF91F9`) проверена собственным разбором. Для остальных каналов соответствие «канал = соленоид» не установлено.

## 5. Разбор мифа: «температурное окно ГДТ 23 / 27 / 90 / 140 °C»

В сообществе ходила трактовка констант `0x8F00 = 9000` («90.0 °C»), `0x8F08 = 2700`, `0x8F0A = 2300` («27 / 23 °C»), `0x8EFC = 16000` и функции `0x26EE0` как «размыкание при перегреве, DTC 34». Проверено по дизассемблеру — **это напряжения, не температура**:

- `0x20D78…0x20E6A` — единственное место записи `0xFFFF906C` и `0xFFFF906E`: `raw × 0x62A2 (25250) / 1024` из буферов АЦП `0xFFFF89BA / 0xFFFF89BC` (10 бит). Полная шкала 25.25 В через делитель = **напряжение питания, две линии, в мВ**; `0xFFFF906A / 0xFFFF9068` — их скользящие средние; третий канал `raw × 2500 / 1024 → 0xFFFF8D84` (0–2.5 В).
- `0x1FB3E`: если `[0xFFFF8626] == 1` и `9000 < [906C] < 16000` → `[8626] = 2`. Это **9.0 В < U < 16.0 В → «питание в норме»**.
- `0x2738A–0x273DA` сравнивает `0xFFFF9084 / 0xFFFF9082` (пишутся в `0x20EA6–0x20ED8` как `raw × 5000 / 1024`, шкала 5 В) с 2700 / 2300 — плаузибилити датчика 2.3–2.7 В, результат — код ошибки.
- `0x26EE0`: если `[0xFFFF8B88] == 1` и `[906C] − [0x8EFA = 1000] > [906E]` и `[906E] ≤ [0x8EFE = 2500]` → **код ошибки 0x2D (45)** (вторая линия питания более чем на 1 В ниже первой и ниже 2.5 В). Контроль питания, не DTC 34.
- Весь блок скаляров `0x8EE0–0x8F0E` — 2560, 1000, 9000, 11000, 9000, 7000, 500, 9000, 1500, 16000, 9000, 6500, 7000, 1000, 16000, 2500, 9000, 16000, 7000, 7000, 2700, 2300, 2504, 4500 — читается как пороги в мВ. К этому же блоку относятся `0x8EE8 / 0x8EEA / 0x8EF0`, см. документ 05.

## 6. Где на самом деле температура ATF

`0x21522`: `a0 = 0xFFFF8435` — сырой байт датчика, `0xFF` = недостоверен. `0x2164C–0x21668`: `[0xFFFF8435] × 3 / 4 → [0xFFFF90D4]` — этот байт уходит в диагностический кадр (байт 6 «кадра 0B 03»). Каноническая шкала BMW для этого поколения `°C = сырое × 0.75 − 48` даёт:

> **T(ATF) = байт кадра − 48 °C**

**Требует проверки (25.09.2026).** Буфер приёма кадра DME2 начинается с `0xFFFF8434` (байт 0), байт 2 лежит в `0xFFFF8436`. Если буфер непрерывный, `0xFFFF8435` это байт 1 кадра DME2, а не АЦП датчика ATF. Это вывод из двух доказанных адресов буфера, кодом 0x21522 он не перепроверен. Сырое ATF модуля переключения и нижнего уровня ГДТ это `0xFFFF90D0` (документ 04 §3).

Ноль шкалы подтверждён косвенно: таблица `0x9A6E` с осью `83 / 93 / 103 / 113` читается по `0xFFFF90D5`, это уже градусы. Температура ATF работает в логике в трёх местах: термодерейт (документ 05 §2), нижний уровень ГДТ (0x320DC, §4) и выбор программ при перегреве (`0xFFFF90E4`, сырое `0xFFFF90D0` от 170: программы PC и PD со своими группами блокировки, §3). Холодные поправки гидравлики это семейство `0xA2C6` (документ 01 §5). Прежнее утверждение «минимальной температуры включения блокировки нет» опровергнуто: ниже сырого ATF 70 (около 22 °C) муфта не замыкается.

## 7. AGS: адаптивный выбор программы (не ГДТ)

> **Прочтение до 23.09.2026 было неверным.** Прежние §1-§4 этого документа описывали функции ниже как блокировку ГДТ: «лесенка из четырёх ступеней» управляющей величины `0xFFFF9216`, пороги включения 0x901E-0x915E, «скважность» 0x888C. 23.09.2026 разбор всех обращений к `0xFFFF9216` показал, что в выходы она не идёт: её читают только рампы, минимумы и сравнения в арбитраже программ (0x23156-0x231CE) и в лестнице уровней 0x8886 (0x1DD18). Это AGS, адаптивный выбор программы переключения. Муфту ГДТ эти функции и таблицы не трогают. Сторонний реверс, который называл 0x888C «уровнями адаптивной программы», был прав.

AGS копит очки `0xFFFF9216` (0..255), по ним определяется уровень 1-4, а уровень выбирает программу. В D уровни 1-2 дают P0 / P1 (матрицы 14 / 06), в S уровни 3-4 дают P2 / P3 (матрицы 11 / 15), документ 01 §5.

| Адрес | Что |
|---|---|
| `0x1DEBC`, функции `0x1Fxxx` | адаптивный выбор программы, читают ветку D / S `0xFFFF91CB` |
| `0x1F14A` | пишет очки `0xFFFF9216`, поднимает их по таблицам 0x88D8 / 0x88E8 |
| `0x1DF6C` | выбирает пару таблиц D / S из 0x901E-0x915E по `0xFFFF91CB` |
| `0x1E11E-0x1E230` | привод очков: рампы к «домашним» и снижение (три строки ниже) |
| `0x1E12A-0x1E19C` | тянет очки к «домашним» 0x888C-0x888F |
| `0x1E1A2` | снижает очки в ветке S (шаг 0x88B0) |
| `0x1E220` | выход при педали ниже порога 0x819C / 0x819D |
| `0x1DCB2`, `0x1DBA4` | ограничение очков `[0x887C + 91CB, 0x8878 + 91CB]` |
| `0x1DD18` | лестница уровней 0x8886 |
| `0x23156-0x231CE` | арбитраж программ по очкам |
| `0x1E848` | 2D-интерполятор |
| `0x9B00-0x9B28` | каталог указателей на таблицы 0x901E-0x917E (документ 01 §3) |

Алгоритм `0x1DEBC` по прежнему разбору дизассемблера, названия исправлены:

```
условия запуска:
    [0xFFFF9113] == 0                    нет кикдауна
    [0xFFFF90E2] <  2
    [0xFFFF90C7] <  5                    положение селектора (внутренний код)
    [0xFFFF9182] >  0x819C / 0x819D      педаль выше порога ветки (3 / 8)
    [0xFFFF9200] == 0                    пауза после прошлой смены истекла

таблица = пара текущей передачи [0xFFFF91AE], вторая таблица пары, если [0xFFFF91CB] == 1
для i = 1 .. [0x8214]-1:
    порог[i] = таблица(X = i, Y = [0xFFFF918F] обороты выходного вала / 32)
уровень = самый высокий i, у которого порог[i] <= [0xFFFF9182], иначе 1
[0xFFFF91AC] = уровень
[0xFFFF9200] = [0x8E88]
```

Параметры (все относятся к AGS, не к муфте):

| Адрес | Сток | Что |
|---|---|---|

| `0x88C0` | 5 | скорость роста очков к «домашним» |

Очки `0xFFFF9216` зажимаются в `[0x887C + 91CB, 0x8878 + 91CB]` (0x1DCB2, также 0x1DBA4). В D (ветка 0) это 32…128, уровни 1-2 (программы P0 / P1), в S (ветка 1) 129…255, уровни 3-4 (P2 / P3). Поэтому в S уровни 1 и 2 неразличимы.

Таблицы 0x901E-0x915E: пары D / S, пару выбирает 0x1DF6C по `0xFFFF91CB`. Значение это порог педали коробки (0..254) для целевого уровня AGS, строки это скорость в n_вых / 32. Все 2D8, X = 1..3 (столбец = порог уровня 2 / 3 / 4). На референсной машине строки 31 / 62 / 94 / 125 / 156 / 188 это 37 / 73 / 111 / 148 / 184 / 222 км/ч. Проценты в скобках ниже это значение / 255 педали коробки, а не доля хода педали.

Прежние выводы из этих таблиц о муфте сняты: «на крейсере в 5-й муфта не уходит со ступени 1» и «ограничение блокировки до 114 км/ч это излом оси 4-й передачи» описывали AGS, а не блокировку. Пороги муфты задаёт 0x993A (§3).

**Как это правили пресеты (v10, v18-v20, документ 08).** Ветка 0: столбец 1 со строки скорости 62 (2-я, 3-я), 113 (4-я), 94 (5-я) опущен до 102 (40 %). Ветка 1: столбец 1 опущен до 26…38 (10-15 %) с щадящим заходом на нижних строках. «Домашние» очки 0x888C стали 32 / 128 / 176 / 240, рост 0x88C0 стал 7, шаг снижения 0x88B0 -10 / -20 / -40. Задумано это было как раннее и более крепкое замыкание муфты. На деле правки меняют AGS: уровень 2 в D тянется к 128 вместо 96, уровни S к 176 / 240 вместо 160 / 224, очки растут со скоростью 7 вместо 5. D на 40-60 % педали дольше держит уровень 2 (P1) без 5-й, S дольше держит уровень 4 и медленнее с него падает. Муфту ГДТ эти правки не трогают.

Замер из прежнего §1 (ручной режим, 3-я, педаль 225/255, 100-142 км/ч: скольжение 128, 256, 160, 128, 96, 64, 0, 0 об/мин «при неизменной ступени») описывает работу настоящей муфты (§2-§4), а не уровень AGS.
