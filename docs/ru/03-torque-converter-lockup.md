# 03 · Блокировка гидротрансформатора (WÜK / TCC)

## 1. Главное

- Блокировка в GS8.60.0 — **лесенка из четырёх ступеней** управляющей величины (константа `0x8214 = 4`), а не «включено/выключено» и не регулятор с целевым проскальзыванием. Таблиц целевого скольжения как класса нет; скольжение — это то, что остаётся при данной ступени и данном моменте. Подтверждено замером: ручной режим, 3-я, педаль 225/255, 100 → 142 км/ч при неизменной ступени — скольжение 128, 256, 160, 128, 96, 64, 0, 0 об/мин.
- Пороги ступеней заданы **в педали 0..255**, ось Y таблиц — **скорость в км/ч**. Температура ATF в логике выбора ступени не участвует ни разу. Отдельного «лимита блокировки по скорости» нет.
- Есть две ветки порогов (документ 01 §4). Гистерезиса в выборе ступени нет — его роль играет пауза `0x8E88 = 5` циклов после смены ступени.

## 2. Код

| Адрес | Что |
|---|---|
| `0x1DEBC` | выбор ступени |
| `0x1E11E–0x1E230` | привод управляющей величины: рампы, матрицы переходов |
| `0x1E848` | 2D-интерполятор |
| `0x9B00–0x9B28` | каталог 11 указателей на таблицы (документ 01 §3) |

Алгоритм `0x1DEBC` (по дизассемблеру):

```
условия запуска:
    [0xFFFF9113] == 0                    не аварийный режим
    [0xFFFF90E2] <  2
    [0xFFFF90C7] <  5                    положение селектора (внутренний код)
    [0xFFFF9182] >  0x819C / 0x819D      педаль выше минимума ветки (3 / 8)
    [0xFFFF9200] == 0                    пауза после прошлой смены истекла

таблица = пара текущей передачи [0xFFFF91AE]; вторая таблица пары, если [0xFFFF91CB] == 1
для i = 1 .. [0x8214]−1:
    порог[i] = таблица(X = i, Y = [0xFFFF918F] скорость км/ч)
ступень = самая высокая i, у которой порог[i] <= [0xFFFF9182]; иначе 1
[0xFFFF91AC] = ступень;  [0xFFFF9200] = [0x8E88]
```

Доказательство, что `0xFFFF9182` — педаль: те же адреса читаются как ось Y матриц точек переключения (документ 02 §1). Дальше ступень переводится в управляющую величину `[0xFFFF9216]` (0..255) по лесенке `0x888C`, с рампами:

| Адрес | Сток | Что |
|---|---|---|
| `0x888C…0x888F` | **32 / 96 / 160 / 224** | величина по ступеням 1–4 (12.5 / 37.6 / 62.7 / 87.8 %). Эвристика каталога видит здесь «таблицу 0x888A 4×1» — на самом деле это лесенка + 4 байта 32 |
| `0x88C0` | 5 | нарастание за цикл (подъём ступени всегда медленный) |
| `0x88C1` | 3 | спад за цикл |
| `0x889C` | 4×4: 0 / 191 / 129 / 129 … | матрица переходов, ветка 0: строка = новая ступень, столбец = прежняя; значение < 128 — нарастание с этой скоростью, ≥ 128 — спад со скоростью 256 − значение: на шаг вниз 191 → −65, на два-три 129 → −127 |
| `0x88B0` | 4×4: 0 / 239 / 223 / 191 … | то же, ветка 1: −17 / −33 / −65 (мягче) |
| `0x8E88` | 5 | пауза после смены ступени, циклов |
| `0x819C / 0x819D` | 3 / 8 | минимум педали по веткам |
| `0x82B0 / 0x82B1` | 78 / 1 | опора «100 %» для `0xFFFF9182 = x·100/78` из `0xFFFF8439` / предел скорости изменения (`0xFFFF917A`) |
| `0x8884 / 0x8886` | 65 / 129 / 193 | альтернативная лесенка (аварийная ветка привода) |

**Что не доказано:** цепочка от `[0xFFFF9216]` до конкретного канала ШИМ. Драйвер токов 0x2054C–0x205F4 обслуживает три канала (`вход × усиление[0xFFFF8CEE/8CF2] / период + смещение[0xFFFF8CF0/8CF4]`), регистры TPU `0xFFFFFF24 / 0xFFFFFF34` и CTM `0xFFFFF43C` реальные, но «какой канал = какой соленоид» не установлено. Поэтому «скважность 32/255» — управляющая величина, а не измеренный ток EDS. Один из чужих реверсов трактовал 0x888C как «уровни адаптивной программы» — с логикой 0x1DEBC это не сходится, но упомянуть обязаны.

## 3. Таблицы порогов

Все 2D8, X = 1..3 (столбец = порог перехода на ступень 2 / 3 / 4), Y = км/ч, значение = педаль 0..255.

| Передача | Ветка 0 | Ветка 1 | Ось Y (км/ч) |
|---|---|---|---|
| 1 | `0x901E` | `0x903E` | 20, 28, 32, 38, 44, 50 |
| 2 | `0x905E` | `0x907E` | 31, 47, 62, 68, 76, 85 |
| 3 | `0x909E` | `0x90BE` | 62, 77, 94, 105, 116, 125 |
| 4 | `0x90DE` | `0x910E` | 63, 88, 113, 125, 138, 147, 156, 166, 181, 188 |
| 5 | `0x913E` | `0x915E` | 31, 63, 94, 125, 156, 188 |
| — | `0x917E` 6×6 | | не расшифрована (соседняя, читается тем же каталогом) |

Стоковые значения (столбцы 1 / 2 / 3):

| Передача | Ветка 0 | Ветка 1 |
|---|---|---|
| 1 | 153 / 230 / 252 (60 / 90 / 99 %) везде | 102 / 166 / 204 (40 / 65 / 80 %) |
| 2 | 153 / 230 / 252 | 64 / 115 / 179 (25 / 45 / 70 %) |
| 3 | 153 / 230 / 252, плоско | 64 / 115 / 179 |
| 4 | 128, 129, 132, 134, 137, 139, 144, 151, 172, 191 / 242 / 252 — **растёт** со скоростью | 64 → 88 / 97 → 141 / 128 → 204 |
| 5 | **230** / 242 / 252 (90 %) везде | 64 / 115 / 179 |

Следствия для стока: в ветке 0 на крейсере в 5-й муфта не уходит со ступени 1 (порог 90 % педали недостижим); в 5-ю она попадает уже «замкнутой» из 4-й и держится, пока педаль выше 25 % (ветка 1) — и только у 4-й порог зависит от скорости, причём с ростом скорости он **растёт**. Обсуждаемое в сообществе «ограничение блокировки до 114 км/ч» на этой прошивке — не скаляр и не сравнение в коде, а излом оси 4-й передачи (63 / 88 / **113** / 125 …) и первый порог педали в этих строках.

Замер на референсной машине (лог под тягой, дроссель > 5°): D 1–3 на 17–46 км/ч — скольжение 160…736 об/мин, ни одного замкнутого кадра; D 4-я на 48–65 км/ч — до 704; S 4-я — замкнут 100 % кадров. Нагрев ATF в городе — прямое следствие.

## 4. Как это правили (пресет v10/v18, документ 08)

Ветка 0: столбец 1 в строках выше 62 км/ч (2-я, 3-я), 113 км/ч (4-я), 94 км/ч (5-я) → 102 (40 %). Ветка 1: столбец 1 → 26…38 (10–15 %) с щадящим заходом на нижних строках. Лесенка `0x888C` → 32 / 128 / 176 / 240, `0x88C0` → 7, `0x88B0` → −10 / −20 / −40. Первая передача и матрица `0x889C` не тронуты. Замыкать муфту насухо ниже ~1500 об/мин на бублике с большим пробегом — дрожь; поэтому на 63 км/ч в 4-й/5-й оставлен щадящий порог.

## 5. Разбор мифа: «температурное окно ГДТ 23 / 27 / 90 / 140 °C»

В сообществе ходила трактовка констант `0x8F00 = 9000` («90.0 °C»), `0x8F08 = 2700`, `0x8F0A = 2300` («27 / 23 °C»), `0x8EFC = 16000` и функции `0x26EE0` как «размыкание при перегреве, DTC 34». Проверено по дизассемблеру — **это напряжения, не температура**:

- `0x20D78…0x20E6A` — единственное место записи `0xFFFF906C` и `0xFFFF906E`: `raw × 0x62A2 (25250) / 1024` из буферов АЦП `0xFFFF89BA / 0xFFFF89BC` (10 бит). Полная шкала 25.25 В через делитель = **напряжение питания, две линии, в мВ**; `0xFFFF906A / 0xFFFF9068` — их скользящие средние; третий канал `raw × 2500 / 1024 → 0xFFFF8D84` (0–2.5 В).
- `0x1FB3E`: если `[0xFFFF8626] == 1` и `9000 < [906C] < 16000` → `[8626] = 2`. Это **9.0 В < U < 16.0 В → «питание в норме»**.
- `0x2738A–0x273DA` сравнивает `0xFFFF9084 / 0xFFFF9082` (пишутся в `0x20EA6–0x20ED8` как `raw × 5000 / 1024`, шкала 5 В) с 2700 / 2300 — плаузибилити датчика 2.3–2.7 В, результат — код ошибки.
- `0x26EE0`: если `[0xFFFF8B88] == 1` и `[906C] − [0x8EFA = 1000] > [906E]` и `[906E] ≤ [0x8EFE = 2500]` → **код ошибки 0x2D (45)** (вторая линия питания более чем на 1 В ниже первой и ниже 2.5 В). Контроль питания, не DTC 34.
- Весь блок скаляров `0x8EE0–0x8F0E` — 2560, 1000, 9000, 11000, 9000, 7000, 500, 9000, 1500, 16000, 9000, 6500, 7000, 1000, 16000, 2500, 9000, 16000, 7000, 7000, 2700, 2300, 2504, 4500 — читается как пороги в мВ. К этому же блоку относятся `0x8EE8 / 0x8EEA / 0x8EF0`, см. документ 05.

## 6. Где на самом деле температура ATF

`0x21522`: `a0 = 0xFFFF8435` — сырой байт датчика, `0xFF` = недостоверен. `0x2164C–0x21668`: `[0xFFFF8435] × 3 / 4 → [0xFFFF90D4]` — этот байт уходит в диагностический кадр (байт 6 «кадра 0B 03»). Каноническая шкала BMW для этого поколения `°C = сырое × 0.75 − 48` даёт:

> **T(ATF) = байт кадра − 48 °C**

Ноль шкалы подтверждён косвенно: таблица `0x9A6E` с осью `83 / 93 / 103 / 113` читается по `0xFFFF90D5` — это уже градусы. Единственное применение температуры в логике — термодерейт (документ 05 §2). Холодные поправки гидравлики — семейство `0xA2C6` (документ 01 §5), в блокировке их нет. Минимальной температуры включения блокировки в этой прошивке **нет**.
