# 01 · Устройство прошивки GS8.60.0 (19C0 / 19D0)

Всё ниже относится к Bosch GS8.60.0 с образом **256 КБ** и программой **19x0** (метка `B22K4_04 19D0` по 0x4322). Проверено на двух дампах: сток E39 2.5 (калибровка `19C0 KA20`) и Alpina B3 3.3 E46 (калибровка `19D0 620P`). Дампы GS8.60.4 (512 КБ, например 20C0 с E46 330i) имеют **другую раскладку**, ничего из этого документа к ним не применимо: см. документ 11.

Покрытие 19x0: адреса полностью, роли частично. В `catalog/gs8600_19d0.json` и собранном из него XDF 899 записей, 842 таблицы + 57 констант, в том числе все 536 таблиц из §2. Роли: 76 записей доказаны кодом (адрес инструкции в `proof`), 637 перенесены из XDF v2.1 без перепроверки, 184 только форма, 2 гипотезы.

## 1. Железо и образ

| | |
|---|---|
| Процессор | Motorola 68k семейства CPU32 (MC68336/376: в коде есть `muls.l`/`divs.l`, регистры SIM `0xFFFFFAxx`, TPU RAM `0xFFFF00xx`). Дизассемблер capstone `CS_ARCH_M68K`, режим `M68K_040` (иначе не декодируются `muls.l`) |
| Порядок байт | big-endian |
| Образ | 262 144 байта; вектор сброса в 0x0000: SP = `0xFFFF828E`, PC = `0x00000400` |
| RAM | `0xFFFF8000–0xFFFF9E00` (так объявлен сегмент 4 в таблице DS2, см. §6). Все переменные в этой документации даны как 32-битные адреса `0xFFFFxxxx` |
| Системный тик | 1 мс (PIT: `0x16E6A move.w #$152,$fa22`, `0x16E70 move.w #$108,$fa24`); счётчик `0xFFFF82A2`. Все пять главных задач регистрируются с периодом 10 (0x16ED4, `moveq #$a,d1`) — **задача 10 мс** |

### Карта памяти

| Диапазон | Содержимое |
|---|---|
| `0x00000–0x00400` | таблица векторов |
| `0x00400–0x08000` | загрузчик, стартовый код, драйвер DS2 (диспетчер 0xC8E–0xF84), блоки идентификации (`A5 A5 …`): 0x4322 `B22K4_0419D0 1423642 1423642`, 0x5FB6 `B22K4_04 … 0260002429 BX…`; таблицы диспетчера DS2 0x3E54 / 0x3E8A (§6) |
| `0x08000–0x10000` | **окно калибровки** — единственное, что правится. Это ровно то, что флешер называет Partial (32 КБ) |
| `0x080D0–0x0E4A2` | зона таблиц внутри окна (см. §2) |
| `0x0E49A–0x0FFCE` | 6964 байта `0xFF` (свободно) |
| `0x0FFCE–0x10000` | метка калибровки `B22K4_0419C0KA20` ×3 + 2 байта по `0xFFFE`: контрольная сумма калибровки, CRC-16/XMODEM по `0x8000–0xFFCD` (0x47DB у стока, 0x1851 у Alpina). | `0x3B372–0x3CBCC` | записи автомата переключения (наборы kind0..3) и их директории, см. документ 04 |
| `0x3CEE0–0x3F77C` | `0xFF` |
| `0x3F77C` | финальный блок идентификации |

**Код 19C0 и 19D0 одинаков байт-в-байт** в `0x10000–0x40000` (SHA-256 области `e151733e1cc1a779975680a48722e26ac43c5b3674150576a38fb0b9e57c2546`). Область `0x0000–0x8000` у двух блоков различается в 129 байтах: 0x4B78–0x4B97 (маркеры `A5A5`), 0x5FDB–0x5FE1 (12-символьная строка вида `BX…` — похоже на серийный номер блока) и 0x6002–0x605B (записи истории программирования — гипотеза). Калибровка 0x8000–0x10000 различается в 2547 байтах. Поэтому: **один XDF на обе программы, полный дамп содержит идентификаторы конкретного блока.**

## 2. Формат таблиц

```
2D8  : [u16 nx][u16 ny][nx байт ось X][ny байт ось Y][nx·ny байт данных]   данные по строкам Y
2D16 : то же, оси и данные 16 бит
1D8  : [u16 n][n байт ось][n байт данных]
1D16 : [u16 n][2n байт ось][2n байт данных]
```

Оси **строго возрастают** — по этому признаку таблицы и находятся (`tools/egs_tables.py scan`). В зоне `0x080D0–0x0E4A2` так находятся **536 таблиц** (15 284 байта). Остаток зоны — скаляры, матрицы без осей (0x889C, 0x88B0, 0x8D92), каталоги указателей (0x9ADC) и 1D-кривые из 2–3 точек, которые эвристика намеренно пропускает (их около сотни, они входят в записи автомата переключения). Утверждение старых заметок «зона замощается без остатка» неверно.

Обращение к таблице из кода всегда одно и то же:

```
pea.l   <адрес указателя на таблицу>   ; из каталога или записи
move.b  <вход X>, d0
move.b  <вход Y>, d1
clr.w   d2
jsr     <интерполятор>
```

Интерполяторы: `0x1E848` — 2D 8 бит, `0x1EB18` — 2D 16 бит, `0x1E680` / `0x1E710` — 1D; в модуле переключения — `0x2CA2A` (2D) и `0x2E462` (lookup − 128, для таблиц-поправок с нейтралью 128).

## 4. Две ветки калибровки — флаг 0xFFFF91CB

Байт `[0xFFFF91CB]` переключает два набора параметров: 0 = ветка 0 (D, а также M после нажатия +/-), 1 = ветка 1 (S). Это признак S, доказано кодом 0x242EE-0x24370 (разбор 23.09.2026). Ветку читают функции AGS, адаптивного выбора программы (0x1DEBC и функции 0x1Fxxx, документ 03 §7), и таблица 0x81A0 (документ 05 §4). Блокировку ГДТ через неё не настроить. Функция `0x242EE-0x24370` (упрощённо):

```
[0xFFFF91CB] = 0
если [0xFFFF916C] != 0 и [0x8975] == 254            → 1
иначе индекс = (селектор − 1)·3 + [0xFFFF91F0]
      по [0xFFFF903A] == 2: байт 0x8D92 + индекс     иначе: байт 0x8D78 + индекс
      если байт == 254                               → 1
```

Таблицы 3 байта на положение селектора (проверено по дампу):

| Селектор | 0x8D92 | 0x8D78 |
|---|---|---|
| 1 | 9, 9, 8 | 9, 9, 8 |
| 2 | 255, **254**, 8 | **254, 254**, 8 |
| 3 | 255, **254**, 8 | **254, 254**, 8 |
| 4 | 255, **254**, 8 | 255, **254**, 8 |
| 5–7 | 0, 0, 0 | 0, 0, 0 |

То есть с завода ветка 1 включена для положений селектора 2-4 в подрежиме 1. Флаг равен 1 в кулисе до нажатия +/- (`0xFFFF916C` и `0x8975` = 0xFE) или когда таблица селектора даёт 0xFE. В D обе таблицы дают 0xFF, и флаг равен 0: код 0xFE в D возможен только при `0xFFFF91F0` = 1 (кнопка программы, у Steptronic её нет). После нажатия +/- флаг снова 0, и работает признак M `0xFFFF91F3`. По коду 0x230F0-0x23106 он равен 1 только при коде программы `0xFFFF8784` = 0x0B или 0x0D, а эти коды ставит только 0x230A8-0x230D2: рычаг в кулисе (код 8), `0xFFFF91F5` = 2, после нажатия +/- (событие `0xFFFF9169`, защёлка `0xFFFF916B`). В таблицах селектора 0x8D74 / 0x8D8E и в байте 0x8975 кодов 0x0B / 0x0D нет, поэтому в D и в S до нажатия признак M равен 0. Что значат «селектор 2/3/4» и «подрежим» по отдельности, до конца не разобрано.

Чем различаются ветки (все адреса — окно калибровки):

| Параметр | Ветка 0 (D) | Ветка 1 (S) |
|---|---|---|
| таблицы AGS: порог педали по скорости для целевого уровня (пару выбирает 0x1DF6C) | 0x901E, 0x905E, 0x909E, 0x90DE, 0x913E | 0x903E, 0x907E, 0x90BE, 0x910E, 0x915E |
| AGS: шаг снижения очков (0x1E1A2, ветвление по `0xFFFF91CB`). 0x889C это пара для ветки 0, отдельно не разобрана | 0x889C | 0x88B0 |
| порог педали функции AGS: ниже порога функция выходит через 0x1E220, уровень не сбрасывается, а замораживается | 0x819C = 3 | 0x819D = 8 |
| 0x81A0 (строка Y) | 30 / 30 / 255 / 255 | 15 / 15 / 30 / 30 |
| 0x98CE (строка Y) | 0 / 43 / 86 / 128 | 129 / 171 / 213 / 255 |

**Важно:** модуль исполнения переключения (гидравлика, 0x34000+) флаг `0xFFFF91CB` **не читает**. Давления и времена одинаковы для D и S/M. «Спортивной гидравлики» отдельной ветки в этой прошивке нет.

Ошибка, которую здесь уже делали: бит 2 в таблице атрибутов программ `0x88F2 + k` **не** включает ветку 1 — функция 0x222D4 пишет 5 в `0xFFFF90C2`, назначение которого не установлено.

## 5. 16 программ переключения и дескрипторы

Активная программа P0…PF хранится в `0xFFFF91A0`. Матрицу для неё выбирает таблица в функции 0x24BA4 (каталог указателей 0x9B2C), поэтому номер матрицы k не равен номеру программы. `0xFFFF91B0` это принудительная программа (значения 0 / 4 / 5), а не активная. Матрицы точек: 0x91B2 + k × 0x70 (документ 02). Роли матриц по коду (разбор 23.09.2026):

| k | Адрес | Программа и роль | Основание |
|---|---|---|---|
| 00 | 0x91B2 | P4: ступень `0xFFFF90CD` = 1, приоритет выше D и S | код 0x24BA4, 0x23230 |
| 01 | 0x9222 | P5: ступень `0xFFFF90CD` = 2, перекрывает S на уровне AGS 3 и работает в D. Не спорт | код |
| 02 | 0x9292 | P6: ступень `0xFFFF90CD` = 3, перекрывает S всегда и работает в D. Не спорт | код |
| 03 | 0x9302 | PF: замена D при `0xFFFF91CA` = 2 и очках AGS не выше 192 | код |
| 04 | 0x9372 | PE: замена D при `0xFFFF91CA` = 1 и очках AGS не выше 64 | код |
| 05 | 0x93E2 | PA: роль не установлена. По форме удержание (вверх 250 везде) | форма |
| 06 | 0x9452 | **P1: основная D, уровень AGS 2** | код |
| 07 | 0x94C2 | PC: D при перегреве ATF (`0xFFFF90E4`), с 5-й | код |
| 08 | 0x9532 | PD: M при перегреве ATF (код программы 0x0D) | код |
| 09 | 0x95A2 | P8: кулиса без логики Steptronic (`0xFFFF91F5` не равно 2). Не M | код |
| 10 | 0x9612 | **PB: основная M** (Steptronic, код программы 0x0B) | код. Байт 22 кадра в M = 178 = 0xB2: программа B в старшей тетраде (документ 06 §3) |
| 11 | 0x9682 | **P2: S, уровень AGS 3** | код |
| 12 | 0x96F2 | P9: роль не установлена. По форме только 1-2 (на 30, это 35 км/ч на референсной машине), выше 2-й не идёт | форма |
| 13 | 0x9762 | P7: роль не установлена. По форме старт со 2-й (1-2 = 0), похоже на зимний режим | форма |
| 14 | 0x97D2 | **P0: основная D, уровень AGS 1** | код |
| 15 | 0x9842 | **P3: S, уровень AGS 4** | код |

Роли «по форме» из прежней версии этой таблицы (01/02 спорт, 03/04/07 D, 08/09/10 ручные, 00 не используется) сняты 23.09.2026: роли выше взяты из таблицы 0x24BA4 и из логики выбора программы. Роли k5 (PA), k12 (P9), k13 (P7) по коду не установлены, для них осталось описание по форме.

Выбор программы (разобран 23.09.2026): 0x2300C, арбитраж 0x23110, разрешение 0x23230 с таблицей пар «код, приоритет» 0x11868 и картой 0x11864 = 0, 1, 2, 3.

- D: уровень AGS 1 или 2 даёт P0 или P1. Замены с приоритетом: PE при `0xFFFF91CA` = 1 и очках AGS не выше 64, PF при `0xFFFF91CA` = 2 и очках не выше 192, PC при перегреве ATF (`0xFFFF90E4`, сырое `0xFFFF90D0` от 170).
- S: уровень AGS 3 или 4 даёт P2 или P3. Очки AGS в S зажаты в 129…255 (0x1DCB2), поэтому уровни 1 и 2 в S неразличимы (документ 03 §7).
- M: код программы 0x0B даёт PB, код 0x0D (при перегреве ATF) даёт PD.
- Кулиса без логики Steptronic (`0xFFFF91F5` не равно 2) даёт P8.
- Ступень `0xFFFF90CD` = 1 / 2 / 3 даёт P4 / P5 / P6 с приоритетом выше D и S: ступень 2 перекрывает S на уровне AGS 3, ступень 3 перекрывает S всегда. Ступень считает 0x1651E из величины 0x8D04 = f(0x8D9C, 0x8D06), сброс в 0x165A0 (эти три адреса в разборе записаны без префикса 0xFFFF, вероятно, это RAM).

Что ступени `0xFFFF90CD` горные (величина 0x8D04 похожа на сопротивление движению, в k0 / k1 / k2 передачи держатся всё дольше), это гипотеза, не доказано. Смысл `0xFFFF91CA` не установлен. Температура ATF, при которой включаются PC и PD, оценена по таблице 0x9A82 примерно в 120 °C: гипотеза, не доказано.

Дескрипторы `0x3AA60`: 5 записей × 32 указателя (шаг 0x80). Слот 12 → шесть карт 2D16 4×5 `0xA2C6 / 0xA304 / 0xA342 / 0xA380 / 0xA3BE / 0xA3FC` (ось X 140/150/180/255 сырых единиц температуры, значения −80 или 0) — холодные поправки. Слоты 13–15 → 16 таблиц 4×4 в `0xA066–0xA20A` — назначение не расшифровано (это **не** пороги ГДТ, как утверждалось в одном из чужих отчётов).

## 6. Диспетчер DS2

Диспетчер 0xC8E–0xF84, таблица команд `0x3E54` — 9 записей `[cmd][pad][ptr32]`:

| Команда | Обработчик | Что |
|---|---|---|
| 0x00 | 0x0F8A | идентификация |
| 0x06 | 0x1088 | **чтение памяти** по сегментам |
| 0x07 | 0x112E | запись памяти |
| 0x0A | 0x1360 | контрольные суммы: CRC-16 трёх областей функцией 0x221C (документ 07 §6) |
| 0x0D | 0x152E | блок 0x3E0E |
| 0x90 / 0x91 | 0x1598 / 0x1708 | флеш |
| 0x9E / 0x9F | 0x17D2 / 0x17F2 | — |

Неизвестная команда → ответ `0xFF` (0xCFC). **Команды 0x0B в этой прошивке нет** — «кадр 0B 03», который читает INPA/логгеры, это job тестера, который внутри использует чтение памяти 0x06.

Таблица сегментов `0x3E8A`, 8 записей `[тип][pad][начало32][конец32]`:

| Тип | Диапазон | Что |
|---|---|---|
| 0, 2, 6, 15 | 0x000000–0x040000 | ROM |
| 3 | 0x000000–0x000100 | EEPROM (через I²C, 0x1D58) |
| **4** | **0xFF8000–0xFF9E00** | **RAM** |
| 1, 5 | пусто | — |

Как этим пользоваться для логирования — документ 06.

## 7. Что такое «сток» в этом репозитории

Стоковая калибровка, относительно которой сделаны все рецепты: программа 19D0, метка калибровки `B22K4_0419C0KA20`, SHA-256 окна 0x8000–0x10000 `d3c2c3fdffb943f5bd848f672c6d3750a79986167c59c72dac367d386cbbdf51`. Сам дамп в репозитории не публикуется — он содержит идентификаторы блока и, в EEPROM, может содержать VIN. У вас на руках должен быть **свой** дамп; `tools/egs_tables.py info` покажет, совпадает ли код и метка.
