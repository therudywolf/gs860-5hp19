# 06 · DS2 и логирование

## 1. Физика

K-line, адрес блока **0x32**, **только 9600 бод** — GS8.60.0 не отвечает на повышенных скоростях, которые умеют некоторые патченые DME; логгер, работающий с обоими блоками, должен держать 9600 либо переключать скорость на каждый запрос. Блок не отвечает, если после ответа другого блока не выдержать паузу (в референсном логгере — 150 мс и один повтор; после оптимизации — 40 мс паузы и таймаут 250 мс, ≈8–10 кадров/с при опросе только EGS).

Кадр: `<адрес> <длина> <данные…> <XOR>`; длина считает весь кадр, включая себя и контрольную сумму; сумма — XOR всех предыдущих байт. Ответ: `<адрес> <длина> <A0 | B0 | A1 | A2> …` (A0 — ок, B0 — команда не принята, A1 — занят/ошибка, A2 — нет данных).

## 2. Команды, которые есть в прошивке

Диспетчер (документ 01 §6): `0x00` идентификация, **`0x06` чтение памяти**, `0x07` запись, `0x0A` контрольная сумма, `0x0D`, `0x90/0x91` флеш, `0x9E/0x9F`. Всё остальное — `0xFF`. Команды `0x04` (ошибки), `0x05` (стереть), `0x0B 0x03` (статус) в таблице 0x3E54 **отсутствуют**: то, что тестеры показывают как «кадр 0B 03» (тело 24 байта), — это job тестера, собирающий значения чтением RAM через 0x06. Поэтому «байты 12 / 17 / 20» — байты RAM-блока, адрес которого задаёт job, в ROM их раскладки нет.

Чтение RAM: команда `0x06`, **сегмент 4**, диапазон `0xFF8000–0xFF9E00` (таблица `0x3E8A`). Точный формат аргументов `0x06` (сегмент, адрес, длина) в этих заметках не задокументирован — снимать трассой с заводского тестера (INPA/DIS) на job’ах статуса и повторять; формат ответа — те же байты, что в RAM.

## 3. Тело «кадра 0B 03» (24 байта) — что расшифровано по логам

| Байт | Что | Масштаб / статус |
|---|---|---|
| 0 | обороты ДВС | × 32 |
| 1 | обороты турбины | × 32 |
| 2 | обороты выходного вала | × 32; скорость = байт × 32 / k (на референсной машине k = 27.11 об/мин на км/ч) |
| 3 | педаль | ≈ × 3.6 (0…255 → %); полный газ без кикдауна ≈ 229 |
| 4 | градиент оборотов | знаковый |
| 6 | температура ATF | **°C = байт − 48** (`[0xFFFF90D4] = [0xFFFF8435] × 3/4`, документ 03 §6) |
| 7 | напряжение борта | × 0.0813 В (по корреляции) |
| 12 | **255 = идёт переключение** | доказано по логу (все кадры с 255 вплотную к смене байта 20). В ROM записи 0xFF нет — гипотеза: job выводит флаг `0xFFFF9717/9718` |
| 17 | картина соленоидов MV1/MV2/MV3 (биты 7/6/5): 1/2-я → 192, 3-я → 64, 4-я → 0/64, 5-я → 160 | совпадает с таблицей `0x12E30` (документ 04 §13) |
| 18 | рычаг: 220 = P, 140 = R, 236 = N, 44 = D, 46 = D в S/M, 172 = переход | по логу |
| 20 | **передача × 32** (32 … 160) | доказано по логу; промежуточные значения только в момент переключения |
| 21 | флаги: 192 = переключение; бит 0 = M; биты 4/5 — тапы | не полностью |
| 22 | программа: 0 = D, 34 = S, 178 = M | по логу |

Скольжение ГДТ = байт 0 − байт 1 (× 32) — считать **только под тягой** (дроссель > 5°, расход воздуха > ~90 кг/ч): на сбросе газа скольжение падает к нулю независимо от муфты, и любая статистика «замкнут N %» без фильтра по нагрузке — мусор.

Ограничение статусного кадра: при чередовании с опросом DME кадр EGS обновляется раз в ~1.3 с, переключение длится 0.3–0.8 с — длительность переключения этим кадром не измеряется. Для измерений нужен режим «только EGS» с чтением RAM.

## 4. Что читать из RAM для A/B гидравлики

Команда 0x06, сегмент 4, период 10–20 мс. Адреса и смысл — из реверса модуля исполнения (документ 04):

| RAM | Что | Метрика |
|---|---|---|
| `0xFFFF9717` / `0xFFFF9718` | переключение идёт / последовательность давления идёт | длительность (аналог байта 12 = 255) |
| `0xFFFF9735`, `0xFFFF973D` | номер фазы, таймер фазы (× 10 мс) | длительность фаз 2, 4, 9, 10 |
| `0xFFFF966C` (s16) | скольжение до синхронизации цели, об/мин | время от старта фазы 9 до \|966C\| ≤ 100 — это «время скольжения»; всплеск / провал |
| `0xFFFF97B4`, `0xFFFF97B2` (u16) | турбина, n_вых | провал турбины при повышении / перелёт при понижении |
| `0xFFFF9720`, `0xFFFF9783` | давление включаемого / выключаемого (0..255) | форма рампы; упор в f24 (116/138) = слишком малое целевое время |
| `0xFFFF96AE`, `0xFFFF9666` | поправка регулятора, отклонение времени скольжения | если 96AE постоянно велика — цель нереальна |
| `0xFFFF965E`, `0xFFFF9668`, `0xFFFF9480/9482/9484` | адаптации | дрейф после прошивки |
| `0xFFFF958C` | давление EDS1 (/50) | контроль выхода |
| `0xFFFF97A0` (u16) | момент ДВС, Нм | привязка к оси Y карт (Y = Нм/4 + 25) |
| `0xFFFF9725` | турбина/32 при старте | ось X карт давления |
| `0xFFFF971A`, `0xFFFF971B` | тип перехода, kind | какая запись работала |
| `0xFFFF9182`, `0xFFFF918F`, `0xFFFF91B0`, `0xFFFF91CB` | педаль, скорость км/ч, программа, ветка | выбор передачи и ГДТ |
| `0xFFFF91AC`, `0xFFFF9216` | ступень ГДТ, управляющая величина ГДТ | блокировка |

Критерий «лучше» для гидравлики: короче фаза 10 при том же моменте, без роста пика d(турбина)/dt после синхронизации, без выхода `0xFFFF9720` на f24, без перелёта турбины на понижении более ~150 об/мин выше синхронных новой передачи, и `0xFFFF96AE` не растёт от переключения к переключению (иначе адаптация «бьётся» с калибровкой).

## 5. Грабли

1. Не убивать логгер жёстко: блок DME может остаться на повышенной скорости, и следующий сеанс его не найдёт — завершать корректно.
2. Два процесса на одном порту дерутся («multiple access on port»); сначала гасить фон.
3. При разборе кадра всегда проверять длину: последний байт — XOR, а не данные.
4. Пик оборотов между опросами теряется — не делать выводов о максимумах по редкому кадру.
