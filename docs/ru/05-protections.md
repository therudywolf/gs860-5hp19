# 05 · Защиты, аварийный режим, монитор напряжения

## 1. Функция 0x265F4 и константы 0x8EE8 / 0x8EEA / 0x8EF0 — монитор напряжения питания (доказано)

Переменные `0xFFFF906C` и `0xFFFF906E` пишутся **только** в функции `0x20D78…0x20E6A`:

```
020d8e  movea.l #$ffff89bc, a1      ; буфер АЦП, канал B (16 бит: старший/младший байт)
020dac  muls.l  #$62a2, d0          ; × 25250
020dba  divs.l  d5, d0              ; / 1024   (d5 = 0x400)
020dbe  move.w  d0, $ffff906e       ; = U_B, мВ  (0xFFFF906A — скользящее среднее ×4/5)
020de4  movea.l #$ffff89ba, a1      ; канал A
020dfc  muls.l  #$62a2, d0
020e08  move.w  d0, $ffff906c       ; = U_A, мВ  (0xFFFF9068 — среднее)
020e46  muls.l  #$9c4, d0           ; третий канал: × 2500 / 1024 → 0xFFFF8D84 (шкала 2.5 В)
```

10-битный АЦП × 25250 / 1024 = полная шкала **25.25 В через делитель**: это два измерения напряжения питания в мВ. Обороты ДВС и турбины живут в других переменных (`0xFFFF97B0` из `0xFFFF8DB2`, CAN × 40/256; `0xFFFF97B4` из `0xFFFF8DE2`, документ 04 §3).

Кто читает эти переменные:

| Код | Что делает |
|---|---|
| `0x1FB3E` | если `[0xFFFF8626] == 1` и `0x8F00 (9000) < [906C] < 0x8EFC (16000)` → `[0xFFFF8626] = 2` — «питание 9…16 В в норме» |
| `0x265F4` | три флага (см. листинг ниже): `|[906C] − [906E]| > 0x8EF0 (1500)` — каналы расходятся больше 1.5 В, проверка пропускается; `[906E] ≥ 0x8EE8 (9000)` — флаг −4(a6); иначе `[906E] ≥ 0x8EEA (7000)` — флаг −6(a6). Далее — порог по ATF `([0xFFFF90D0] − 45) × 38 + 10000`, × `[0x8B60]` / 10000 + `[0x8B62]` → `0xFFFF8FB2`, цикл по трём элементам `0x1263C` с `0xFFFF8D80`; потребитель флагов `0x266B2` — диагностика исполнительных цепей с порогами, зависящими от напряжения |
| `0x21DAE` | `cmpi.w #10000, [906E]` — порог 10.0 В |
| `0x26EE0` | если `[0xFFFF8B88] == 1` и `[906C] − 0x8EFA (1000) > [906E]` и `[906E] ≤ 0x8EFE (2500)` → код ошибки `0x2D` (45): канал B более чем на 1 В ниже канала A и ниже 2.5 В |

```
02660e  move.w  $ffff906c, d0
026614  movea.l #$ffff906e, a3
02661a..026632                    ; d0 = |[906C] − [906E]|
026636  cmp.w   $8ef0, d0         ; 1500 мВ
02663c  bhi     $2665e            ; разошлись — дальше не проверяем
02663e  move.w  (a3), d0          ; [906E]
026640  cmp.w   $8ee8, d0         ; 9000 мВ
026646  bcs     $26650
026648  move.w  #1, -4(a6)        ; U_B ≥ 9.0 В
02664e  bra     $2665e
026650  cmp.w   $8eea, d0         ; 7000 мВ
026656  bcs     $2665e
026658  move.w  #1, -6(a6)        ; 7.0 В ≤ U_B < 9.0 В
```

Весь блок скаляров `0x8EE0–0x8F0E` (2560, 1000, 9000, 11000, 9000, **7000**, 500, 9000, **1500**, 16000, 9000, 6500, 7000, 1000, 16000, 2500, 9000, 16000, 7000, 7000, 2700, 2300, 2504, 4500) — пороги в мВ; к нему же относится «температурный» миф из документа 03 §5.

**История ошибки.** В сентябре 2026 по эксперименту (серия газовок на нейтрали: пик 6613 — норма, выход на отсечку ~7008 → через 1.3 с аварийный режим и код 0x95 в памяти) круглые константы 7000/9000/1500 в `0x265F4` были прочитаны как «обороты турбины / ДВС», а функция — как «защита по разносу турбины». Записи переменных при этом не проверили. В пресете **v17** на этом основании `0x8EEA` было поднято до 7300 — то есть сдвинут порог 7.0 В → 7.3 В, к оборотам это отношения не имеет. **Ошибка исправлена в v18: 0x8EEA = 7000 (сток).** Все три константы оставлять стоковыми.

Что остаётся открытым:

- наблюдение «выход ДВС на отсечку ~7000 → аварийный режим, 6613 — нет» реально и воспроизводимо, но его причина **не найдена**. Кандидаты (гипотезы): контроль передаточного отношения / плаузибилити оборотов турбины против ДВС в другом модуле; условие в CAN-обработке при активной отсечке DME. Ищется по методу документа 10;
- код ошибки 0x95 (149) в памяти EGS — таблица соответствия внутренних номеров кодам DS2 не найдена, связь с событием не доказана.

## 2. Термодерейт по ATF

Единственное применение температуры ATF в логике (документ 03 §6):

| Адрес | Что |
|---|---|
| `0x9A6E` | 1D8, ось `83 / 93 / 103 / 113` °C → значения `170 / 90 / 55 / 0`; читается по `0xFFFF90D5` (0x28DCA), результат → счётчик `0xFFFF920F` |
| `0x9A78` | вторая таблица (нули) → `0xFFFF9210` |
| `0x25E54–0x25E6C` | счётчики убывают каждый цикл |
| `0x28D50` | при `[0xFFFF920F] == 0` ограничивает **эффективную педаль** `0xFFFF9184` (сама она зажата сверху настоящей педалью `0xFFFF9182`) |

Смысл: чем горячее масло, тем меньше «бюджет времени» на полную педаль; при 113 °C он равен нулю. Это защита по **максимуму** температуры. Через педаль она косвенно влияет на точки переключения и на пороги блокировки ГДТ (они заданы в педали). Минимальной температуры, ниже которой что-то запрещается, в этой цепочке нет. Холодное поведение гидравлики — семейство `0xA2C6…0xA3FC` (2D16 4×5, ось 140 / 150 / 180 / 255 сырых единиц ≈ 57 / 65 / 87 / 143 °C, значения −80 или 0), слот 12 дескрипторов `0x3AA60`.

## 3. Аварийный режим — как он выглядит в кадре

Наблюдение по логу (не реверс): при переходе в аварийный режим в теле «кадра 0B 03» разом меняются пять байт — байт 12 `0x1E → 0xFF`, байт 14 `0x08 → 0xFF`, байт 17 `0xC2 → 0x02`, байт 18 `0xDC → 0xDD`, байт 20 `0x20 → 0x80`. Перезапуск двигателя снимает режим; ошибка в памяти остаётся. Признак аварийного режима в RAM — `0xFFFF9113` (проверяется в 0x1DEBC как условие запуска блокировки). Чужие списки «12 триггеров аварийного вектора 0xFFFF8FA2» по коду не подтверждены и здесь не приводятся.

## 4. 0x81A0 / 0x81B2 — не гидравлика и не «фазы соленоидов»

Две таблицы 2D8 4×2 (`X = 0 / 166 / 167 / 194`, `Y = 0 / 1`), сток `0x81A0`: `30 30 255 255 / 15 15 30 30`; `0x81B2`: `15 × 8`. В ранних заметках назывались «длительностями фаз переключения» / «фазами соленоидов». Реверс 16.09: они читаются через список `0x9AE0[2] / [3]` функцией `0x1E848(0x9AE0, X = 0xFFFF9197, Y = 0xFFFF91CB)` из модуля выбора передачи `0x1F4xx` и сравниваются с `0xFFFF9176`. `0xFFFF9197` = **обороты ДВС / 32** (`0xFFFF8DB2` = CAN `0xFFFF842E` × 40/256, /32): ось X = 0 / 5312 / 5344 / 6208 об/мин; Y = ветка калибровки. Смысл сравнения — гипотеза (удержание/запрет решения о переключении при высоких оборотах; 255 = условие никогда не выполняется). К исполнению переключения отношения не имеет; в v10 строка ветки 1 менялась на 10/10/20/20 — в v17 возвращена к стоку.
