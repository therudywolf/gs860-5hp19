# 05 · Защиты, аварийный режим, монитор напряжения

## 1. Функция 0x265F4 и константы 0x8EE8 / 0x8EEA / 0x8EF0 — монитор напряжения питания (доказано)

Переменные `0xFFFF906C` и `0xFFFF906E` пишутся **только** в функции `0x20D78…0x20E6A`:

```
020d8e  movea.l #$ffff89bc, a1      ; буфер АЦП, канал B (16 бит: старший/младший байт)
020dac  muls.l  #$62a2, d0          ; × 25250
020dba  divs.l  d5, d0              ; / 1024   (d5 = 0x400)
020dbe  move.w  d0, $ffff906e       ; = U_B, мВ  (0xFFFF906A — скользящее среднее ×4/5)
020de4  movea.l #$ffff89ba, a1      ; канал A
020dfc  muls.l  #$62a2, d0
020e08  move.w  d0, $ffff906c       ; = U_A, мВ  (0xFFFF9068 — среднее)
020e46  muls.l  #$9c4, d0           ; третий канал: × 2500 / 1024 → 0xFFFF8D84 (шкала 2.5 В)
```

10-битный АЦП × 25250 / 1024 = полная шкала **25.25 В через делитель**: это два измерения напряжения питания в мВ. Обороты ДВС и турбины живут в других переменных (`0xFFFF97B0` из `0xFFFF8DB2`, CAN × 40/256; `0xFFFF97B4` из `0xFFFF8DE2`, документ 04 §3).

Кто читает эти переменные:

| Код | Что делает |
|---|---|
| `0x1FB3E` | если `[0xFFFF8626] == 1` и `0x8F00 (9000) < [906C] < 0x8EFC (16000)` → `[0xFFFF8626] = 2` — «питание 9…16 В в норме» |
| `0x265F4` | три флага (см. листинг ниже): `|[906C] − [906E]| > 0x8EF0 (1500)` — каналы расходятся больше 1.5 В, проверка пропускается; `[906E] ≥ 0x8EE8 (9000)` — флаг −4(a6); иначе `[906E] ≥ 0x8EEA (7000)` — флаг −6(a6). Далее — порог по ATF `([0xFFFF90D0] − 45) × 38 + 10000`, × `[0x8B60]` / 10000 + `[0x8B62]` → `0xFFFF8FB2`, цикл по трём элементам `0x1263C` с `0xFFFF8D80`; потребитель флагов `0x266B2` — диагностика исполнительных цепей с порогами, зависящими от напряжения |
| `0x21DAE` | `cmpi.w #10000, [906E]` — порог 10.0 В |
| `0x26EE0` | если `[0xFFFF8B88] == 1` и `[906C] − 0x8EFA (1000) > [906E]` и `[906E] ≤ 0x8EFE (2500)` → код ошибки `0x2D` (45): канал B более чем на 1 В ниже канала A и ниже 2.5 В |

```
02660e  move.w  $ffff906c, d0
026614  movea.l #$ffff906e, a3
02661a..026632                    ; d0 = |[906C] − [906E]|
026636  cmp.w   $8ef0, d0         ; 1500 мВ
02663c  bhi     $2665e            ; разошлись — дальше не проверяем
02663e  move.w  (a3), d0          ; [906E]
026640  cmp.w   $8ee8, d0         ; 9000 мВ
026646  bcs     $26650
026648  move.w  #1, -4(a6)        ; U_B ≥ 9.0 В
02664e  bra     $2665e
026650  cmp.w   $8eea, d0         ; 7000 мВ
026656  bcs     $2665e
026658  move.w  #1, -6(a6)        ; 7.0 В ≤ U_B < 9.0 В
```

Весь блок скаляров `0x8EE0–0x8F0E` (2560, 1000, 9000, 11000, 9000, **7000**, 500, 9000, **1500**, 16000, 9000, 6500, 7000, 1000, 16000, 2500, 9000, 16000, 7000, 7000, 2700, 2300, 2504, 4500) — пороги в мВ; к нему же относится «температурный» миф из документа 03 §5.

**История ошибки.** В сентябре 2026 по эксперименту (серия газовок на нейтрали: пик 6613 — норма, выход на отсечку ~7008 → через 1.3 с аварийный режим и код 0x95 в памяти) круглые константы 7000/9000/1500 в `0x265F4` были прочитаны как «обороты турбины / ДВС», а функция — как «защита по разносу турбины». Записи переменных при этом не проверили. В пресете **v17** на этом основании `0x8EEA` было поднято до 7300 — то есть сдвинут порог 7.0 В → 7.3 В, к оборотам это отношения не имеет. **Ошибка исправлена в v18: 0x8EEA = 7000 (сток).** Все три константы оставлять стоковыми.

**Спорно, кодом не перепроверено.** Разбор 23.09.2026 пишет, что калибровки со значением 7000 по адресам 0x8EEA, 0x8EF8, 0x8F04, 0x8F06 сравниваются со значениями, пришедшими по CAN. Листинг выше (разбор 16.09.2026) показывает сравнение 0x8EEA с `0xFFFF906E`, напряжением бортсети в мВ, которое пишется в 0x20D78. Оба прочтения сходятся в одном: это не обороты турбины. С чем сравниваются 0x8EF8 / 0x8F04 / 0x8F06, не расписано ни в одном из разборов.

Что остаётся открытым:

- **Закрыто 23.09.2026.** Причина аварийного режима у отсечки найдена: монитор турбины 0x26C84 с порогом [0x8B44] = 6720 (§6). Пик 6613 ниже порога, выход на отсечку около 7008 выше него, аварийный режим через 1.3 с. Константы 0x8EE8 / 0x8EEA / 0x8EF0 к этому отношения не имеют.
- код ошибки 0x95 (149) в памяти EGS — таблица соответствия внутренних номеров кодам DS2 не найдена, связь с событием не доказана.
- Что DS2-код 0x95 это внутренняя ошибка 0x25 монитора турбины, гипотеза, не доказано: таблица кодов DS2 для 19D0 не найдена.

## 2. Термодерейт по ATF

Термодерейт по ATF (документ 03 §6). Это не единственное применение температуры ATF: она участвует ещё в нижнем уровне ГДТ (0x320DC: до сырого 70 муфта разомкнута, выше сырого 160 без скольжения, документ 03 §4) и в выборе программ при перегреве (`0xFFFF90E4`: программы PC и PD, документ 01 §5).

| Адрес | Что |
|---|---|
| `0x9A6E` | 1D8, ось `83 / 93 / 103 / 113` °C → значения `170 / 90 / 55 / 0`; читается по `0xFFFF90D5` (0x28DCA), результат → счётчик `0xFFFF920F` |
| `0x9A78` | вторая таблица (нули) → `0xFFFF9210` |
| `0x25E54–0x25E6C` | счётчики убывают каждый цикл |
| `0x28D50` | при `[0xFFFF920F] == 0` ограничивает **эффективную педаль** `0xFFFF9184` (сама она зажата сверху настоящей педалью `0xFFFF9182`) |

Смысл: чем горячее масло, тем меньше «бюджет времени» на полную педаль, при 113 °C он равен нулю. Это защита по **максимуму** температуры. Через педаль она косвенно влияет на точки переключения и на таблицы AGS, которые здесь раньше назывались порогами блокировки ГДТ (они заданы в педали, документ 03 §7). В цепочке термодерейта минимальной температуры, ниже которой что-то запрещается, нет, но нижний уровень ГДТ ниже сырого ATF 70 (около 22 °C) держит муфту разомкнутой (документ 03 §4). Холодное поведение гидравлики задаёт семейство `0xA2C6…0xA3FC` (2D16 4×5, ось 140 / 150 / 180 / 255 сырых единиц ≈ 57 / 65 / 87 / 143 °C, значения −80 или 0), слот 12 дескрипторов `0x3AA60`.

## 3. Аварийный режим — как он выглядит в кадре

Наблюдение по логу (не реверс): при переходе в аварийный режим в теле «кадра 0B 03» разом меняются пять байт: байт 12 с `0x1E` на `0xFF`, байт 14 с `0x08` на `0xFF`, байт 17 с `0xC2` на `0x02`, байт 18 с `0xDC` на `0xDD`, байт 20 с `0x20` на `0x80` (4-я передача в битах 7-5, документ 06 §3). Перезапуск двигателя снимает режим, ошибка в памяти остаётся. Признак аварийного режима в RAM это `0xFFFF90C1`: его ставит 0x222A2 по биту 3 слова масок `0xFFFF8FA2`, в кадре 0B 03 это бит 0 байта 18 (отсюда 0xDC и 0xDD). `0xFFFF9113`, который здесь раньше назывался признаком аварийного режима, это признак кикдауна, а 0x1DEBC, где он проверяется, это функция AGS (документ 03 §7). `0xFFFF8FA2` это слово масок реакции ошибок: его собирает 0x1A71A по таблице 0x8366, бит 3 = аварийный режим, бит 8 = запрет блокировки ГДТ (§6). Чужие списки «12 триггеров аварийного вектора 0xFFFF8FA2» по коду не подтверждены и здесь не приводятся.

## 4. 0x81A0 / 0x81B2 — не гидравлика и не «фазы соленоидов»

Две таблицы 2D8 4×2 (`X = 0 / 166 / 167 / 194`, `Y = 0 / 1`), сток `0x81A0`: `30 30 255 255 / 15 15 30 30`; `0x81B2`: `15 × 8`. В ранних заметках назывались «длительностями фаз переключения» / «фазами соленоидов». Реверс 16.09: они читаются через список `0x9AE0[2] / [3]` функцией `0x1E848(0x9AE0, X = 0xFFFF9197, Y = 0xFFFF91CB)` из модуля выбора передачи `0x1F4xx` и сравниваются с `0xFFFF9176`. `0xFFFF9197` = **обороты ДВС / 32** (`0xFFFF8DB2` = CAN `0xFFFF842E` × 40/256, /32): ось X = 0 / 5312 / 5344 / 6208 об/мин; Y = ветка калибровки. Смысл сравнения — гипотеза (удержание/запрет решения о переключении при высоких оборотах; 255 = условие никогда не выполняется). К исполнению переключения отношения не имеет; в v10 строка ветки 1 менялась на 10/10/20/20 — в v17 возвращена к стоку.

| `0xDF06…DF14` / `0xDEC4, 0xDEC9, 0xDECE, 0xDED3` | 20/16/12/16 … 116/138/138/87 | мин/макс давления скольжения (f23/f24). f24 для 1-2 / 2-3 / 3-4 / 4-5 это потолок, в который упирается регулятор, и предохранитель от удара (документ 04 §14) |

| `0x8EE0–0x8F0E` | — | пороги диагностики напряжений |

## 6. Монитор турбины 0x26C84 (причина аварийного режима у отсечки)

Найдено 23.09.2026. Задача 50 мс (список задач 0x121DE) вызывает 0x26C84: если обороты турбины `0xFFFF8DE2` (сырой канал 1) не ниже [0x8B44], ставится ошибка 0x25 (подкод 7) через 0x1A3FA. Других условий нет: ни передача, ни P/N, ни скорость не нужны. До аварийного режима проходит около секунды, короткий выход за порог проходит без последствий.

| Адрес | Команда | Что |
|---|---|---|
| `0x26C8E` | `movea.l #$FFFF8DE2,a4` | обороты турбины, сырой канал 1 |
| `0x26C96` | `cmp.w $8B44.l,d0` | сравнение с порогом |
| `0x26D14` | `moveq #$25,d0` | номер ошибки 0x25 |

Порог `0x8B44` (u16): сток 6720 об/мин турбины, на 0x8B44 в коде одна ссылка (поиск по всему образу). Подтверждено вторым независимым разбором.

Реакцию задаёт таблица масок 0x8366, 4 байта на ошибку: для 0x25 это элемент 0x8366 + 4 × 36 = 0x30000009, бит 3 = аварийный режим. 0x1A71A собирает маски в слово `0xFFFF8FA2`, 0x222A2 по биту 3 ставит признак аварийного режима `0xFFFF90C1`: 4-я передача, регуляторы давления выключены. В кадре 0B 03 это бит 0 байта 18 (`0xFFFF91BE`, документ 06 §3). Бит 8 слова `0xFFFF8FA2` выключает блокировку ГДТ (документ 03 §2).

Так объясняется наблюдение из §1: пик 6613 ниже порога, выход на отсечку около 7008 выше него, аварийный режим через 1.3 с. Константы 0x8EE8 / 0x8EEA / 0x8EF0 к этому отношения не имеют. Других сравнений оборотов турбины около 7000 в коде нет, кроме 0x2AD9C (7000 / 7001 из 0xB19C), а это деление на диапазоны для выбора таблицы, не защита.

Следствие для тюнинга: заводской порог 6720 ниже отсечки многих моторов. Если турбина держится на отсечке выше 6720 (при замкнутой ГДТ турбина равна мотору), коробка примерно через секунду уходит в аварийный режим. Поднимать 0x8B44 можно только вместе с отсечкой мотора. Сам монитор лучше не отключать: другой защиты турбины от разноса в коде не найдено.

Гипотеза, не доказано: в записи ошибки 0x8464 счётчик 0x14 = 20 это такты по 50 мс, отсюда около секунды до аварийного режима. Также не доказано, что DS2-код 0x95 это внутренняя ошибка 0x25.

Рядом ещё одна защита по оборотам: ошибка 0x21 ставится, когда выходной вал показывает 0, а скорость по CAN выше [0x8B32] (0x26AD6, сток 400). Маска 0x800, аварийного режима нет.
