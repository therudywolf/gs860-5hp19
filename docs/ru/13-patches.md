# 13 · Готовые патчи: ГДТ на 1-й, блокировка ГДТ, прогрев, 5-я в S, обороты, кикдаун, ручной режим

Семь правок, которые просят чаще всего, сделаны инструментом `tools/egs_patch.py` для обеих программ: GS8.60.0 (19C0 / 19D0, образ 256 КБ) и GS8.60.4 (20C0, образ 512 КБ). Каждая опирается на код: у каждого адреса ниже указана инструкция, которая его читает. Из патчей собраны три пресета, документ 14.

«Бублик» ниже это гидротрансформатор (ГДТ), «заблокировать бублик» значит замкнуть его муфту (lock-up, документ 03).

## Коротко

```
python3 tools/egs_patch.py list                          # что делает каждый патч, пресеты, эталонные моторы
python3 tools/egs_patch.py show my_dump.bin              # эти ячейки в вашем образе, ГДТ по программам, точки в пол
python3 tools/egs_patch.py apply my_dump.bin -o build.bin no-warmup tcc-lock manual-hold --cut 6720
python3 tools/egs_patch.py apply my_dump.bin -o build.bin tcc-first:modes=S+M,rpm=1760 s-no5 --spark 6528
python3 tools/egs_patch.py preset sport-daily my_dump.bin -o build.bin --spark 6528 --cut 6720
```

Параметры патча пишутся через двоеточие: `имя:ключ=значение,ключ=значение`. Обороты мотора нужны трём патчам: `--spark` это нижний ограничитель (искра или мягкая отсечка), `--cut` это самая высокая жёсткая отсечка. При замкнутой ГДТ обороты турбины равны оборотам мотора, поэтому все пороги ниже считаются по турбине.

## 0. Как работает инструмент

1. Узнаёт программу по размеру образа и SHA-256 кода (19x0: `0x10000–0x40000`, 20C0: `0x08000–0x70000`). Другое ПО, например BMW GS8.60.4 `15C0`, отклоняется: адреса там другие.
2. Проверяет суммы загрузчика и программы на входе. Не сошлись, значит дамп снят с ошибкой или программа правлена: стоп.
3. Перед записью проверяет то, на что патч опирается: заголовки и оси таблиц, заводские значения, свободные группы ГДТ, свободное место под код. Не совпало, стоп с объяснением.
4. Пишет только калибровку. Исключение одно: `tcc-first` на 19x0 добавляет 52 байта кода (§1).
5. Пересчитывает все три контрольные суммы, проверяет, что вне калибровки и объявленного кода не изменилось ни байта, и пишет `out.bin` и `out.log`: каждый изменённый байт с причиной, старые и новые суммы, SHA-256. Для 19x0 без правки кода пишется и партиал 32K (`out_partial32k.bin`). Для 20C0 партиал не пишется: что флешер читает и пишет как Partial у GS8.60.4, не проверено (документ 11).
6. `--dry-run` печатает журнал и ничего не пишет.

Прежде чем шить, прочитайте документ 07. После прошивки сбросить адаптации.

## 1. ГДТ на первой передаче (`tcc-first`)

**Как в стоке.**

- 19x0: на 1-й муфта не замыкается никогда. Верхний уровень блокировки `0x29056` пропускает передачу, только если её бит есть в маске `[0x8978]` = `0x003C` (2-5-я, `0x29066-0x29078`). Байт группы порогов берётся как `[0x897E + 4 × программа + передача − 2]` (`0x29088-0x290A8`), и для 1-й это байт 5-й передачи предыдущей программы, так что одной маской 1-ю не включить.
- 20C0: маска `[0x7096E]` = `0x007E` (коды передач 1-6, `0x25494`), байты групп `[0x70970 + 6 × программа + код − 1]` (`0x255F6`). D и S на 1-й берут группу 11 (`0x71AD0`): на педали 0-224 порог 202 (никогда), на 230 / 240 / 255 размыкание 10, скольжение 11, замыкание 12 (n_вых / 32). Значит, в пол муфта на 1-й замыкается уже с 1407 об/мин турбины, на частичной педали никогда. У BMW 15C0 на том же месте замыкание только в строке кикдауна, с 1994.

**Что делает патч.** На 1-й ставит свои пороги: на малой педали замыкание с `rpm` об/мин турбины, с ростом педали позже (шаги сборок WOLF4X v41-v44, на которых ездит E39 владельца). С отпущенной педалью (строки педали 0 и 5) не замыкает: при торможении на 1-й муфта размыкается сразу (`coast=1` это отключает).

| Параметр | По умолчанию | Что |
|---|---|---|
| `modes` | `S+M` | `M`, `S+M` или `D+S+M` |
| `rpm` | 1760 | турбина замыкания в S и M на малой педали |
| `rpm_d` | `rpm` + 350 = 2110 | то же для D |
| `coast` | 0 | 1: замыкать и с отпущенной педалью |

Пороги в строках оси педали (размыкание / скольжение / замыкание, об/мин турбины на 1-й, 1 ед. = 117 об/мин). Ось педали у 19x0 0 / 5 / 46 / 59 / 72 / 97 / 122, у 20C0 0 / 5 / 46 / 59 / 72 / 224 / 230 / 240 / 255:

| Строка педали | S и M (rpm 1760) | D (rpm_d 2110) |
|---|---|---|
| 0, 5 | никогда | никогда |
| 46 | 1290 / 1525 / 1759 | 1407 / 1759 / 2111 |
| 59 | 1407 / 1642 / 1876 | 1525 / 1876 / 2228 |
| 72 | 1525 / 1759 / 2111 | 1642 / 1994 / 2463 |
| 97 (19x0) | 1642 / 1994 / 2346 | 1759 / 2111 / 2580 |
| 122 (19x0), 224 (20C0) | 1759 / 2111 / 2463 | 1876 / 2228 / 2697 |
| 230, 240, 255 (20C0) | заводские 1173 / 1290 / 1407 | заводские 1173 / 1290 / 1407 |

- **20C0**: только калибровка. S и M (P2, P3, PB, PD) переводятся на свободную заводом группу 12, её строки пишутся по таблице выше, строки в пол (230+) не позже заводской группы 11. С `D` строки группы 11 переписываются под D, строки в пол остаются заводскими. Патч откажется, если группа 12 уже занята.
- **19x0**: маска `0x003C` → `0x007E`, по свободной заводом группе на S/M и на D (в заводе свободны 5 и 10), таблица «группа 1-й передачи по программе» в `0x3E380` и 52 байта кода в `0x3E380–0x3E3FF` (там `0xFF`). В `0x290A0` три заводские инструкции заменены на `jsr 0x3E3A0` и три `nop`: код делает то же, что заводские инструкции, а для 1-й (и кода 6) берёт группу из таблицы. Это те же байты, что в сборках WOLF4X v41-v44 (проверено побайтно). Код меняется, поэтому **шить только полный образ**: партиал 32K унёс бы маску без кода, и 1-я читала бы чужую группу. Инструмент партиал в этом случае не пишет.

На нижнем уровне муфта по-прежнему не замкнётся, если не пускает автомат муфты: в 19D0 при холодной ATF (до сырого 70, около 22 °C, документ 03 §4), в 20C0 при оборотах мотора не выше поля f24 корня `0xFFFF9808` (1000 или 820 об/мин по записи, `0x4A766`, документ 11 §6).

## 2. Блокировка ГДТ рано и при любой педали (`tcc-lock`)

**Как в стоке.** Верхний уровень сравнивает n_вых / 32 с тремя порогами группы (документ 03 §2-3): ниже «размыкание» муфта открывается, выше «скольжение» идёт регулируемое скольжение, выше «замыкание» муфта замкнута. Группа своя у каждой программы и передачи, пороги растут с педалью. Заводская D у E39 замыкает 3-ю с 4052 об/мин турбины, в пол 2-ю с 5757; у M во 2-й замыкания нет вовсе (документ 03 §3, таблица в документе 12).

**Что делает патч.** Во 2-5-й ставит ровные по педали пороги: замыкание с `rpm` (по умолчанию 1600 об/мин турбины), скольжение с `rpm` − 385, размыкание ниже `rpm` − 512 (значения сборки WOLF4X v25). При нажатии на педаль муфта не размыкается. Порог замыкания не делается позже заводского для S (P3) и M (PB) ни на одной педали.

| Параметр | По умолчанию | Что |
|---|---|---|
| `modes` | `S+M` | `M`, `S+M`, `D+S+M` |
| `rpm` | 1600 | турбина замыкания, 1300-3500 |
| `d_gears` | `3-5` | для D: `3-5` или `2-5` |

Группы, в которые пишет патч: на 19x0 6, 7, 8, 9 (в заводе ими пользуются только PB и PD), на 20C0 5, 8, 9, 10 (в заводе только PB). Если в вашей калибровке эти группы берёт другая программа, патч откажется.

Итог на эталонных образах (об/мин турбины, размыкание / скольжение / замыкание): 2-я 1087 / 1215 / 1599, 3-я 1081 / 1216 / 1621, 4-я 1088 / 1216 / 1600, 5-я 1092 / 1211 / 1543 (19x0, не позже заводской S) или 1591 (20C0).

Что это даёт: в S и M машина едет «на прямой», без проскальзывания ГДТ, меньше греется ATF (документ 03 §3: на E39 в D в городе муфта почти не замыкается). Цена: на малых оборотах под нагрузкой передаются вибрации мотора. На 20C0 прибавка `0x70B98` к порогу повышения действует при замкнутой ГДТ (§5), это нужно учитывать в ручных точках.

## 3. Режим прогрева (`no-warmup`)

**Что это (разобрано кодом 06.10.2026).** После включения блок запускает программу прогрева: 19x0 `0x28D50`, флаг `[0xFFFF90EE]` (ставит `0x15F82`); 20C0 `0x25182`, флаг `[0xFFFF9088]` (ставит `0x10994`). Пока флаг стоит:

- матрицы переключения видят не педаль, а max(педаль, таблица) (19x0 `0x24B66`, 20C0 `0x2072A`). Таблица `0x8142` / `0x7013A` по температуре мотора и программе: P0, P1 и P7 = 102 (40 % педали) до 55 °C, 0 с 65 °C. Значит, на холодном моторе D переключается вверх так, будто педаль нажата на 40 %, то есть позже;
- в 19x0 арбитр программ получает запрос 8, программу P0 (`0x231F8`); в M у кода программы приоритет выше, и запрос не действует. Флаг читает и AGS (`0x1DC1E`).

Температура мотора берётся из CAN DME (байт × 3 / 4 = °C + 48: 19x0 `0x21696`, 20C0 `0x1CE44`). Конец прогрева: n_вых / 32 не ниже `[0x8B48]` / `[0x70BAC]` = 48 (1536 об/мин выходного вала, около 57 км/ч на E39 523i), сигнал DME по CAN, счётчик времени по температуре при включении (`0x9A6E` / `0x71B52`: 170 / 90 / 55 / 0 при 35 / 45 / 55 / 65 °C) или ноль таблицы. Данные у 19x0 и 20C0 одинаковые.

До 06.10.2026 таблица `0x9A6E` в документе 05 и в каталогах называлась «термодерейтом по ATF». Это неверно: температура в ней это температура мотора при включении, а сама таблица это счётчик программы прогрева.

**Что делает патч.** `[конец]` = 0: условие «n_вых / 32 не ниже 0» верно сразу, программа кончается в первом же цикле. Один байт: 19x0 `0x8B48`, 20C0 `0x70BAC` (у каждого одна ссылка в коде: `0x28D6E`, `0x251A0`). Патч откажется, если там не заводское 48 (`force=1` пишет всё равно).

Зачем BMW держит программу прогрева, по коду не установлено: она зависит только от температуры мотора и кончается к 65 °C. Без неё на холодном моторе коробка переключается вверх раньше.

## 4. S без 5-й передачи (`s-no5`)

S это программы P2 и P3 (матрицы k11 и k15), между ними выбирает уровень AGS (документы 01 §5, 11 §5).

**Что делает патч.**

1. 4>5 = 255 во всех строках k11 и k15: в 5-ю S не переходит никогда.
2. 5>4 = порог, при котором понижение из 5-й сажает 4-ю не ближе 500 об/мин к искре (`--spark`). Если перевести рычаг из D в S на 5-й, коробка сразу уходит на 4-ю, если n_вых ниже порога. На эталонных моторах порог это 5984 (M52TUB25, искра 6496) и 6016 (M54B30, искра 6528) об/мин турбины на 4-й.
3. `pin=1` (по умолчанию): нижняя граница очков AGS в S `0x887D` / `0x70891` 129 → 193. S держит уровень 4 (P3, k15), и в S не вмешиваются замена D PF и горная ступень 2 (документ 01 §5). `pin=0` оставляет AGS заводским.

## 5. Обороты переключения в S, D и других картах (`shift-wot` и вручную)

**Единица.** Значение матрицы это n_вых / 32 (документ 02 §3). Обороты турбины на пороге = значение × 32 × передаточное (1-я 3.665, 2-я 1.999, 3-я 1.407, 4-я 1.000, 5-я 0.742). Обратно: значение = обороты турбины / (32 × передаточное), с округлением вниз. Главная пара и колёса сюда не входят.

| Режим | Программы и матрицы | 19x0 | 20C0 |
|---|---|---|---|
| D | P0 = k14, P1 = k6 | `0x97D2`, `0x9452` | `0x7182E`, `0x714AE` |
| S | P2 = k11, P3 = k15 | `0x9682`, `0x9842` | `0x716DE`, `0x7189E` |
| M | PB = k10, при перегреве PD = k8 | `0x9612`, `0x9532` | `0x7166E`, `0x7158E` |

Адрес матрицы k: 19x0 `0x91B2 + k × 0x70`, 20C0 `0x7120E + k × 0x70`. Столбцы 1-4 повышения 1>2…4>5, 5-8 понижения 2>1…5>4. Строки это педаль коробки, у D и S ось 0 / 46 / 83 / 121 / 160 / 198 / 203 / 243 / 244 / 254 / 255, строка 255 это кикдаун. В XDF обоих блоков у матриц в названии стоит роль.

**Правила (документ 02 §4).** Команда на повышение раньше искры на 1120 / 610 / 490 / 400 об/мин для 1>2 / 2>3 / 3>4 / 4>5: пока идёт переключение, мотор ещё раскручивается. Понижение сажает передачу не ближе 500 об/мин к искре и не ближе 6 единиц к повышению. На 20C0 при замкнутой ГДТ к порогу повышения прибавляется `0x70B98` = 4 / 2 / 2 / 5 единиц для 1>2…4>5 (1-2 позже на 469 об/мин турбины, 2-3 на 128, 3-4 на 90, 4-5 на 160; документ 11 §5).

**Патч `shift-wot`** пишет строки педали 243-255 матриц выбранного режима по этим правилам, строки ниже 243 не поднимает выше новых точек, понижения держит под повышениями и под искрой. На 20C0 прибавка вычитается, так что с замкнутой ГДТ команда приходит ровно по правилу, а с открытой раньше на величину прибавки.

| Параметр | По умолчанию | Что |
|---|---|---|
| `modes` | `S` | `S`, `D`, `D+S` (M ставит §7) |
| `rpm` | по правилу | `a/b/c`: турбина команды 1>2 / 2>3 / 3>4 напрямую, не ближе 200 к искре |

Итог на эталонных моторах, турбина в момент команды 1>2 / 2>3 / 3>4: M52TUB25 (искра 6496) 5278 / 5885 / 5988; M54B30 (искра 6528) 5395 / 5885 / 6033 при замкнутой ГДТ, 4926 / 5757 / 5943 при открытой.

**Вручную.** Открыть матрицу в TunerPro (XDF из `xdf/`), посчитать значение по формуле выше, после правки проверить:

```
python3 tools/egs_tables.py shift build.bin --turbine        # все 16 матриц в оборотах турбины
python3 tools/egs_tables.py verify-shift build.bin --spark 6528 --cut 6720 --stock my_dump.bin
python3 tools/gs860_crc.py fix build.bin build_fixed.bin     # после правки в TunerPro
```

`verify-shift` проверяет D, S и M по ролям из кода (на 20C0 с прибавкой при замкнутой ГДТ) и с `--fix out.bin` опускает то, что нарушает правила.

## 6. Без кикдауна (`no-kickdown`)

**Как в стоке.** Кикдаун это флаг (19x0 `[0xFFFF9113]`, функция `0x205FC`; 20C0 `[0xFFFF90B7]`, `0x1BC9C`). Источник выбирает байт:

- 19x0 `[0x8D1A]`, у E39 0: контакт под педалью (бит 7 порта `0xFFFF89BE`, активный 0) и педаль коробки выше `[0x8246]` = 230; не 0: бит DME по CAN.
- 20C0 `[0x70D6A]`, в файле Alpina B3S 1: бит DME по CAN (`[0xFFFF90BA]`); 0: контакт и педаль выше `[0x70232]` = 230.

С флагом матрицы берут строку 255 (19x0 `0x24B34`, 20C0 `0x206F8`), AGS не считается (19x0 `0x1DEC4`, 20C0 `0x1908C`), ручная ветка M пропускается (19x0 `0x2492C`, 20C0 `0x2047E`): в M с педалью в пол кнопки +/- не работают.

**Что делает патч.**

- `scope=all` (по умолчанию): источник = 0 (контакт), порог = 255. Педаль коробки не бывает выше 254, поэтому флаг не ставится никогда. В пол работает строка 254, кнопки в M работают и в пол. Два байта.
- `scope=M`: флаг остаётся, но в матрицах M строка 255 становится равной строке 254, то есть кикдаун в M не понижает. Кнопки в M в пол при этом по-прежнему не работают.

## 7. M без самостоятельных переключений (`manual-hold`)

**Как в стоке.** M это PB (k10), при перегреве PD (k8). В M матрица продолжает работать: столбцы вверх дают самоповышение, столбцы вниз автопонижения, строка 255 кикдаун (документ 02 §5). У E39 заводская M повышает сама с 5747 / 6077 / 6168 об/мин турбины, то есть до отсечки M52TU. У Alpina 20C0 с 5160 / 6525 / 6799 / 6752. От перекрута при ручном понижении защищает не матрица, а таблица минимальной передачи (19x0 `0x8AE2`, 20C0 `0x70B3C`), её патч не трогает.

**Что делает патч.** Пороги вверх M ставятся выше жёсткой отсечки `--cut` не меньше чем на 150 об/мин: под газом мотор упирается в отсечку, а коробка держит передачу. Повышение остаётся только на накате, когда колёса раскручивают турбину выше отсечки. Пороги не ближе 100 об/мин к монитору турбины (документ 05 §6: турбина не ниже порога около секунды даёт ошибку 0x25 и аварийный режим). На 20C0 там, где M может держать муфту замкнутой с отпущенной педалью, учтена прибавка `0x70B98`. Строка кикдауна M не понижает (`kd=0`).

| Параметр | По умолчанию | Что |
|---|---|---|
| `monitor` | заводской | `auto`: поднять монитор ровно настолько, чтобы пороги встали выше отсечки; `число`: свой порог, не выше 7232 (заводское у Alpina 19x0 и 20C0) |
| `up` | `guard` | `never`: 255, без защиты на накате (колёса могут раскрутить мотор выше отсечки) |
| `kd` | 0 | 1: кикдаун в M понижает как завод |

Итог на эталонах, турбина самоповышения 1>2 / 2>3 / 3>4 / 4>5: M52TUB25 (отсечка 6592) 6802 / 6781 / 6754 / 6752, монитор `0x8B44` 6720 → 6912; M54B30 (отсечка 6720) 6920 / 6909 / 6889 / 6880, монитор 20C0 7232 без изменений.

Сразу под этой правкой есть ловушка: отсечку брать **самую высокую** из жёстких (у M54 она зависит от передачи). Если порог встанет ниже реальной отсечки, M повысит сама на полке.

## 8. Кулиса: S или сразу M (`gate`)

Байт программы левой кулисы до первого нажатия +/-: 19x0 `0x8975` (`0x230D8`), 20C0 `0x70966` (`0x1EB88`, `0x1EBE4`).

- `0xFE` (BMW 19C0 и BMW 15C0): в кулисе сначала S (P2 / P3 по уровню AGS), первое нажатие +/- переводит в M.
- `0x0B` (Alpina 19D0 620P и 20C0): M (PB) сразу.

`gate:mode=S` пишет `0xFE`, `gate:mode=M` пишет `0x0B`. У 20C0 есть второй байт, `0x70967` = 3 (P3), когда `[0xFFFF918C]` = 2 (биты 0-1 байта 2 сообщения CAN `0x338`, смысл значения не установлен); патч его не трогает.

## 9. Спортивная S (`s-sport`)

**Зачем.** В файле Alpina 20C0 матрицы S (P2 = k11, P3 = k15) почти равны D (k14, k6): те же точки на педали 83-203. Кулиса Alpina даёт сразу M (`0x0B`), поэтому спортивной программы файлу не требовалось. После `gate:mode=S` уровень S отличался бы от D только патчами `s-no5` и `shift-wot`, а они трогают строки в пол. `s-sport` делает S спортивной и на частичной педали.

**Что делает.** На педали 60-242 точки повышения матриц S идут от заводской точки к точке в пол той же матрицы (строка педали 243, которую `shift-wot` поставил под ограничитель): 20 % пути на педали 83, 35 % на 121, 50 % на 160, 65 % на 198, 67 % на 203, между ними по линейной. Точки понижения идут к понижениям в пол на `down=0.35` этого пути и остаются минимум на 6 единиц ниже своего повышения (без «качелей»). Строки 0-46 (ровная езда) и 243-255 не трогаются, столбец 4>5 после `s-no5` остаётся 255. `strength=` (по умолчанию 1) масштабирует веса.

Порядок в цепочке: после `shift-wot` и `s-no5`. Работает на обеих платформах. Если S в файле уже спортивная (заводской BMW), она сдвинется ещё выше: уменьшите `strength`.

Пример на файле Alpina B3S 20C0 (обороты турбины, ГДТ разомкнута): педаль 160, 1>2 / 2>3 / 3>4 = 2228 / 2751 / 2927 в D, 3518 / 4286 / 4412 в S.

## 10. Жёсткость переключений по нагрузке (`shift-feel`, 20C0 и 19x0)

**От чего зависит жёсткость.** Гидравлические записи (давление, времена, регулятор скольжения) выбираются типом переключения и классом нагрузки; селектор `0x41842` программу D / S / M не читает, а байт варианта `[0xFFFF93C0]` берётся из состояния переключения, не из программы (документ 11 §9). Поэтому «жёсткий M, спортивная S, нежная D» отдельными таблицами не сделать: одни и те же таблицы действуют в любой программе. Отличается нагрузка: D переключается на малой нагрузке, S и M у ограничителя в пол. Патч заставляет таблицы следовать за нагрузкой.

**Что делает.** 20C0 и 19x0 (на 19x0 таблицы лежат в записях вида 1 и 3 модуля `0x34000-0x39600`: время скольжения повышений поле f45 `0x364A2`, понижений f69 и f33 по состоянию `[0xFFFF972C]`, давление включаемого f32 и верхняя граница f24 `0x35DBE`; пары 20C0 те же значения и формы, адреса в `egs_patch.py`, `FEEL`). Общие таблицы 19x0 (`0x0C0C8` на три типа, `0x0C0F0` на два) масштабируются один раз. Пол времени никогда не удлиняет переключение.

- Целевое время скольжения переключений под нагрузкой (5 таблиц повышений, 13 понижений, 3 строки момента турбины, такты по 10 мс) масштабируется по строке: малая строка `up_soft` / `dn_soft` (по умолчанию 1.20 / 1.15, дольше = мягче), средняя 1, большая `up_hard` / `dn_hard` (0.80 / 0.85, короче = чётче), не короче `up_min` / `dn_min` (28 / 15 тактов). Гаражные переключения (N в D, тип 0>2) и понижения 2>1 не трогаются.
- Давление включаемого элемента в фазах скольжения повышений под нагрузкой (4 таблицы 8x10 типов 1>2 … 4>5) растёт на `press` (по умолчанию 0.10) на верхних строках момента, линейно от строки `ramp` (3) до последней; первые три строки не меняются.
- Верхняя граница этого давления (13 байт `0x7B94D`-`0x7B960`) поднимается на `bound` (1.10), иначе регулятор скольжения упирался бы в старый потолок.

**Что доказано, а что нет.** Таблицы и оси доказаны кодом (документ 11 §9); время скольжения это уставка регулятора, поэтому короче уставка = регулятор сам поднимает давление. Единицы давления не установлены; что «больше байт = выше давление», следует из роста таблиц с моментом. Выдержат ли изменение пакеты конкретной коробки, неизвестно: на первом выезде нужен лог (ATF, турбина, передача, состояние ГДТ).

## 11. Чего патчи не делают

- Не трогают гидравлику, оси таблиц, загрузчик и идентификацию. Список запретов в документе 09.
- Не поднимают монитор турбины выше 7232 и не трогают монитор напряжения (`0x8EE8…`, `0x70F32…`: это милливольты, документ 05 §1).
- Не работают с другим ПО (15C0 и прочие): адреса другие, инструмент отказывается.
- Целиком пресеты на машине не проверены (документ 14). На 19x0 аналоги `tcc-lock`, `tcc-first`, `s-no5` и `manual-hold` стоят на референсной E39 (сборки WOLF4X v24-v44), замыкание ГДТ на 1-й логом пока не подтверждено. Проверяйте логом (документ 06).
