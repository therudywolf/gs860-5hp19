# 04 · Исполнение переключения: гидравлика, фазы, давления

Реверс модуля **0x34000–0x39600** (задача 10 мс) по стоковому дампу 19D0. Всё, что не подтверждено байтами или кодом, помечено «гипотеза». Единицы: давление — сырые 0..255 (дальше `×50` → канал EDS через `0x2E41C` → ток/ШИМ в `0x2E296`); время — такты **10 мс**.

## 1. Единицы времени

Δt для таймеров переключения считается так (0x2DBC2):

```
02dbc6  move.w $ffff97ba, d0    ; мс-время задачи (копия 0xFFFF82A2)
02dbd2  sub.w  (a4), d0         ; − предыдущее
02dbec  addq.w #5, d0
02dbee  divu.w #10, d0          ; (Δt + 5) / 10
02dbf2  move.w d0, $ffff94d0    ; = число тактов по 10 мс
```

0x340F2 прибавляет `0xFFFF94D0` к таймерам `0xFFFF9674` (с начала скольжения), `0xFFFF969C` (с начала переключения), `0xFFFF969E` и к байтовым таймерам фаз `0xFFFF973D / 973E / 973F` (насыщение 255). **Все времена в таблицах — в тактах 10 мс.**

## 2. Записи-указатели: как модуль находит свои таблицы

Калибровки гидравлики читаются не напрямую, а через **записи** из 32-битных указателей. Корень `0xFFFF94F8 → 0x3CBCC`; его первое слово — директория `0x3CBBA` из четырёх **наборов** (kind):

| kind (`0xFFFF971B`) | Директория | Записей × полей | Смысл |
|---|---|---|---|
| 0 | `0x3CBA0` | 6 × 34 | Schub-Hoch — повышение без нагрузки |
| **1** | `0x3CB3A` | 6 × 78 | **Zug-Hoch — повышение под нагрузкой** |
| 2 | `0x3CB7A` | 9 × 42 | Schub-Rück — понижение без нагрузки |
| **3** | `0x3CB54` | 9 × 73 | **Zug-Rück — понижение под нагрузкой (kickdown)** |

Формат директории: `[u16 n][n × ptr32 на запись]`; запись — массив полей `f00, f01, …`, каждое поле — `ptr32` на таблицу, 1D-кривую или байт в окне калибровки. Записи kind1 лежат в `0x3B372, 0x3B4AA, 0x3B5E2, 0x3B71A, 0x3B852` (запись 0 = запись 1), kind3 — `0x3BF72 … 0x3C76E`, kind2 — `0x3B98A …`, kind0 — `0x3C892 …`.

**Индекс записи = тип перехода** `0xFFFF971A` из матрицы 7×7 `0x12FDC[из−1][в−1]`:

```
1→2 = 2   2→3 = 3   3→4 = 4   4→5 = 5   2→1 = 2   3→2 = 3   4→3 = 4   5→4 = 5
3→1 = 6   4→2 = 7   5→3 = 8   6(N)↔2 = 1
```

Поэтому «семейство» адресов в каталоге — это **одно и то же поле записи для разных переходов**: например, kind1 f32 = `B6BC (тип 0/1), B656 (1↔2), B80A (2↔3), B974 (3↔4), BADE (4↔5)`.

Выбор набора (0x343B6 → 0x3425E):

- направление `0xFFFF9748` из `0x12FAA` (1 вверх, 2 вниз, 3 вниз через одну);
- класс `0xFFFF9722` (0 = Schub, 1 = Zug) из `0x2E4A8`: нагрузка `0xFFFF97EA` ≥ порог (таблицы набора `0x3CD18` по ATF и n_вых) или n_вых ниже порога → Zug;
- `kind = 0x13012[класс·4 + направление]`: класс 0 → вверх kind0, вниз kind2; класс 1 → вверх kind1, вниз kind3.

Модуль **не читает** флаг ветки `0xFFFF91CB`: гидравлика одна для D и S/M.

## 3. Входы модуля (снимок каждые 10 мс, 0x39516–0x397DC)

| RAM | Источник | Смысл |
|---|---|---|
| `0xFFFF97B4` | фильтр `0xFFFF8DE2` | обороты турбины; `0xFFFF97E2` = /32 (байт) |
| `0xFFFF97B2` | фильтр `0xFFFF8DA8` | обороты выходного вала n_вых; `0xFFFF97E4` = /32 |
| `0xFFFF97A0 / 97A4` | `0xFFFF8D96` через 0x2DFBA / 0x2DFE0 | момент ДВС, Нм; `0xFFFF97DF = 97A0/4 + 25`, `0xFFFF97E0 = 97A4/4 + 25` — **ось Y карт** |
| `0xFFFF97E5` | `0xFFFF90D0` | ATF, сырое (ось многих 1D-кривых, 10…170) |
| `0xFFFF97E9` | `0xFFFF9182` | педаль |
| `0xFFFF97E8 / 97EA` | `0xFFFF9173` → 0x2E082 | нагрузка (класс Zug/Schub) |
| `0xFFFF9595 / 0xFFFF9716` | — | фактическая / целевая передача (7 = не определена, 6 = N/R) |
| `0xFFFF9725` | снимок `0xFFFF97E2` при старте (0x3446C) | турбина/32 в момент начала — **ось X карт давления** |

**Оси всех карт 8×10 / 3×3 / 4×4: X = обороты турбины / 32** (снимок при старте либо текущие), **Y = момент ДВС / 4 + 25** (Y = 85 → 240 Нм, Y = 125 → 400 Нм). Таблицы с нейтралью 128 — знаковые поправки (`lookup − 128`, 0x2E462).

## 4. Старт переключения

0x39238 → 0x3911E → 0x343B6 / 0x35114:

```
039296  move.b (a3), d0          ; целевая 0xFFFF9716
039298  move.b (a5), d1          ; фактическая 0xFFFF9595
03929a  jsr $34b00               ; разрешение
039312  jsr $39086               ; задержка по корню [$80/$84/$88] против 0xFFFF969C
03932a  jsr $3911e               ; СТАРТ
039186  move.b d6, $ffff9717     ; = 1 «переключение идёт»
03918c  move.b d6, $ffff9718     ; = 1 «последовательность давления идёт»
```

Сразу считаются времена записи: `0xFFFF9684 = f02(ATF)` (общее время), `0xFFFF9688 = 9684 − f03`, `0xFFFF9692 / 9694 = f05 / f06(ATF)` (таймауты признания передачи), `0xFFFF9686 = f04(ATF)`; для повышения (0x35494, **всегда по kind1**): `0xFFFF968E = f10(ATF) + f08 + (f12(n_вых) − 128)` = **время наполнения**, `0xFFFF9690 = 968E + f43(n_вых) + корень[$7C] + f27`.

## 5. Фазы

Драйвер фаз 0x36340 (каждые 10 мс): пока 0x3565A («фаза завершена») = 1 → шаг `0xFFFF976B`++ → новая фаза из **`0x13034[шаг·5 + kind]`** → 0x35978 (вход: длительность `0xFFFF96A8`, база давления `0xFFFF96AC`) → сброс таймера фазы `0xFFFF973D`; затем 0x35DBE считает давление включаемого сцепления → `0xFFFF9720`.

Таблица `0x13034` (строки = шаг, столбцы = kind0..3 + спец.):

```
шаг0: 0 0 0 0 0    шаг1: 1 1 1 1 1    шаг2: 2 2 2 2 2    шаг3: 3 3 3 3 3
шаг4: 6 4 5 8 0    шаг5: 6 9 9 8 0    шаг6: 6 10 10 8 7  шаг7: 13 11 11 12 13   шаг8: 255…
```

kind1 (повышение под нагрузкой): **0 → 1 → 2 → 3 → 4 → 9 → 10 → 11**. kind3: 0→1→2→3→8→8→8→12. kind2: 0→1→2→3→5→9→10→11. kind0: 0→1→2→3→6→6→6→13.

| Фаза | Длительность `0xFFFF96A8` | Выход (0x3565A) | Давление включаемого (0x35DBE) | Физика |
|---|---|---|---|---|
| 1 | f08 (байт; 1→2: 0, 2→3: 6) | таймер ≥ длит. | 0x30248(из), если `0x9756 == 1`, иначе 0 | пауза / подготовка |
| 2 | kind1: `0xFFFF968E − f08` = время наполнения; kind3: f31 / f12(n_вых) + f10(ATF) + адаптация f11 | таймер ≥ длит. | `0xFFFF96AC` (= **f13(ATF)** давление быстрого наполнения) + `0xFFFF968C` | **быстрое наполнение (Schnellfüllung)** |
| 3 | корень[$7C] = 1 такт | таймер ≥ и `0x9756` | 0 | разделительный такт |
| 4 | **f27** (байт: 1→2 12, 2→3 11, 3→4 15, 4→5 12 → 110–150 мс) | таймер ≥ **или** флаг `0xFFFF96A6` | (f28(нагрузка) − 128) + **f14(t)** + `0xFFFF96AC` (= f15(ATF) + адаптация 0x2AC6A + `0xFFFF9480`) | **подвод к точке касания (Füllausgleich)** |
| 9 | **f43(n_вых/32)** (1→2: 15–28; 3→4 / 4→5: 20 → 150–280 мс) | таймер ≥ длит. | **f32(турб. старт, момент)** + (f33(t) − 128) + `0xFFFF96AC` (= f29(ATF) + `0xFFFF9668`), рампа от предыдущего за `0xFFFF96A8`, ограничение f23..f24 | **начало скольжения — открытое давление** |
| 10 | f31 (если корень[$9C]) | \|скольжение\| ≤ **f44** (u16 = 100 об/мин) → синхронизация | как 9 + `0xFFFF96AE` (регулятор времени скольжения) + `0xFFFF968C`, ограничение f23..f24 | **регулируемое скольжение до синхронизации** |
| 11 | — | таймер ≥ длит. | f32 + (f33(t + `0xFFFF96AA`) − 128) + **f30(t)** (0 / 10 / 255) + базы | **дожим до полного давления** |
| 12 (kind3) | f46 | таймер ≥ длит. | f00 или 255 | завершение понижения |

Конец переключения (0x3504C → 0x34ECC → 0x34FA8): `0xFFFF969C ≥ 0xFFFF9684` (f02) или фактическая передача (по передаточному числу, `0xFFFF9747`) стала целевой и выдержаны таймауты f05 / f06 → `0xFFFF9717 = 0`, `0xFFFF9716 = цель`; `0xFFFF9718` сбрасывается по завершении последовательности давления.

## 6. Регулятор времени скольжения (0x347DE, 0x364A2, 0x36612, 0x36678)

```
0347fe  move.w $ffff97b2, d0    ; n_вых
034804  muls.l d1, d0           ; × i(цель) из 0x12F9C (×1000)
034808  divs.l #1000, d0
034812  move.w $ffff97b4, d1    ; − турбина
034828  move.w d0, (a1)         ; 0xFFFF966C = скольжение до синхронизации цели, об/мин
```

0x364A2: доля оставшегося скольжения `d7 = (турб·1000 − n_вых·i_цель) / (n_вых·(i_из − i_цель))` (0…1000); затем:

```
036564  move.l $b4(a0), -(a7)   ; kind1: f45 = 3×3 (BFB0 / BF9C / BFEC / C028 / C064)
036568  move.b (a4), d0         ; X = 0xFFFF97E2 турбина/32
03656a  move.b (a2), d1         ; Y = 0xFFFF97DF момент/4+25
03656c  jsr $2ca2a              ; 2D lookup
0365c4  muls.l d7, d0           ; × остаток/1000
0365da  move.b d0, (a5)         ; 0xFFFF9737 = целевое оставшееся время
0365e6..0365fe                  ; 0xFFFF96B6 = 0xFFFF966C·100 / 0xFFFF9737 — требуемый градиент
```

kind3: f33 (`0x84`) при `0xFFFF972C ∈ {3, 4}`, иначе f69 (`0x114`); kind2: f41 — 1D по турбине. 0x36678: отклонение (оценка оставшегося времени 0x36612 − цель) вне мёртвой зоны f16 → коэффициенты f17 / f18 → поправка градиента → `0xFFFF9670` → добавка давления `0xFFFF96AE`.

**Вывод: 3×3 = целевое время фазы скольжения.** Единица — как у таймеров, 10 мс (гипотеза по размерности: 40–80 → 400–800 мс при малом моменте, 26–40 на 5-й и понижениях — совпадает с реальным 5HP19). Меньше значение → регулятор требует больший градиент давления → быстрее и жёстче.

## 7. Давление выключаемого сцепления (0x37664 → 0x37728…0x38218)

```
037b2e  move.l $d4(a0), -(a7)   ; kind1 f53 = BCAE / BD14 (3↔4)
037b34  move.b $ffff97df, d1    ; Y = момент
037b3a  jsr $2ca2a
037b5c  cmp.w d7, d0            ; ≤ f47 (0xBC; макс 82 / 104)
037b78  move.b d0, $ffff9783    ; давление выключаемого
```
```
038168  movea.l $b4(a0), a0     ; kind3 f45 = B73E / B7A4 / B90E / BA78 / BBE2 / B88C / B9F6 / BB60
03816e  move.b $ffff9725, d0    ; X = турбина/32 при старте
0381a4  movea.l $c0(a0), a0     ; + (f48(t) − 128)
```

Выход: 0x353F6 / 0x37664 → канал EDS по `0xFFFF9756 / 9757 / 9758` (0x34DD6 выбирает EDS 3/4 по MV2 для 5-й) → 0x38F68 (нижняя граница `0xFFFF9763` + f34(момент)) → 0x2E41C (канал, значение × 50) → 0x2E296 / 0x2E3CE (ток/ШИМ; для EDS1 копия /50 в `0xFFFF958C`).

## 9. Снятие момента

Шесть карт 2D16 8×8 `0xAB0C / 0xABB0 / 0xAC54 / 0xACF8 / 0xAD9C / 0xAE40`: X = обороты 700 … 6000, Y = нагрузка 0 … 100, значение = **процент момента, который оставляется** на время переключения (сток 25–70 %; строка нулевой нагрузки — 100 либо 40–60). Запрос уходит в DME по CAN; насколько глубоко DME его отработает — вопрос калибровки DME (вне этого репозитория). Эти карты — не «карты целевого скольжения ГДТ», как утверждал один из чужих отчётов.

## 10. Где Alpina быстрее и за счёт чего

Доказано по данным таблиц и их роли в коде:

1. Короче целевое время скольжения при высоком моменте (3×3 kind1 и kind3) — регулятор поднимает градиент давления → быстрее синхронизация.
2. Выше давление включаемого сцепления при ≥ 200 Нм (B974 / BE46 / BEAC) и **ниже** при малом моменте — резче под газом, мягче в городе.
3. Выше давление выключаемого при повышении (BCAE / BD14 +8…10) — меньше провал на перекрытии.
4. Ниже давление выключаемого при понижении под нагрузкой (B73E / B7A4 / B90E) — быстрее отпускает.
5. Время и давление наполнения **не тронуты** (только ось X карт давления расширена до 7000 под мотор Alpina).
6. Фаза 9 у Alpina **длиннее** — быстрота достигается давлением и целевым временем, не обрезанием фаз.

## 11. Почему ранняя сборка «v5» стала неездовой

118 таблиц были записаны с **осями Alpina** и данными **сток + 2 × (Alpina − сток)** (экстраполяция). Последствия по коду:

| Что | Сток → v5 | Что делает код | Симптом |
|---|---|---|---|
| 3×3 целевое время BFEC / C028 / C0C8 / C08C | ×0.30–0.68 при высоком моменте, ось Y 85 → 95 | регулятор требует градиент в 1.5–3 раза выше, давление уходит к f24 (макс.) | удар на 2→3 / 3→4 под газом, рывок на 4→3 / 5→4 |
| давление выключаемого при понижении B73E / B7A4 / B90E | ×0.19–0.47 | сцепление отпускается почти сразу | провал / зависание оборотов, потом удар включения |
| время наполнения D6C2 (1↔2) | ×0.55–1.31 по ячейкам, оси другие | недолив → задержка и хлопок; перелив → удар в начале фазы 4 | грубое 1→2 / 2→1 |
| давление наполнения D01E, поправки CB76 / C9E6 / D2FA / D30A, длительность фазы 9 D670 / D684 / D698 (×2.45), 4×4 B42A… (×0.2–10), 6×6 B582 (×2.4) | искажены с чужими осями | значения читаются по сдвинутым осям — фактически случайные | непредсказуемость по температуре / скорости |
| пороги ГДТ 0x901E–0x915E, точки 0x9222…0x9842 | оси Alpina | смещение порогов | накладывается |

Отсюда правило №1 репозитория: **оси не менять никогда** (документ 09).

## 12. Что трогать и что нет — по коду

Трогать (только строки высокого момента, оси = сток):

- **целевое время скольжения 3×3** — главный «спортивный» рычаг; регулятор сам подберёт давление в пределах f23..f24;
- **давление включаемого в фазе скольжения (kind1 f32)** — только строки ≥ 228 Нм (Y ≥ 82); строки ≤ 100 Нм оставить сток (комфорт);
- **давление выключаемого при повышении (BCAE / BD14)** — до +8…10 (уровень Alpina);
- **давление выключаемого при понижении (B73E / B7A4 / B90E)** — вниз; для B90E оси совпадают с Alpina, можно брать её данные целиком. Поднимать BA78 — в обратную сторону (медленнее 4→3).

Не трогать: время наполнения f10, давление наполнения f13, длительности фаз 4 (f27) и 9 (f43) — Alpina их не сокращает, а ошибки здесь = удар/провал (это и есть v5); поправки по ATF (f15 / f29 / f41 / f42); мин/макс f23 / f24 (f24 — предохранитель от удара); 4×4 kind1 f70 и 6×6 kind3 f65 (семантика не доказана); адаптации f11.

## 13. Кадр диагностики: байты 12 / 17 / 20

Что доказано по RAM:

- **байт 17** («картина сцеплений» 192 / 64 / 0 / 160) = состояния соленоидов MV1 / MV2 / MV3 в битах 7 / 6 / 5 — совпадает с таблицей `0x12E30` (3 MV × 7 передач × 2 режима, читается 0x30312 → 0x2E372 → RAM `0xFFFF9518…951A`): 1-я = 1,1,0 → 192; 3-я = 0,1,0 → 64; 4-я = 0,0/1,0 → 0/64; 5-я = 1,0,1 → 160;
- **байт 20 = передача × 32** — код упаковки в биты 7..5 не найден; гипотеза: форматирует тестер;
- **байт 12 = 255 во время переключения** — записи константы 0xFF в модуле нет; гипотеза: тестер выводит флаг «Schaltung aktiv» (`0xFFFF9717 / 0xFFFF9718`) как 255. Для логгера лучше читать `0xFFFF9717`, `0xFFFF9735`, `0xFFFF973D` напрямую (документ 06).
