# 12 · GS8.60.0 (19D0) and GS8.60.4 (20C0): how they differ

A summary of the differences between the two programs of the same ZF 5HP19 gearbox (Bosch GS8.60 unit). Details with instruction addresses: documents 01–10 (GS8.60.0, software 19C0 and 19D0, 256 KB) and document 11 (GS8.60.4, software 20C0, 512 KB). Only what those documents prove is listed here, with the same confidence levels. Anything not checked is called so.

## Conclusions

1. These are different programs with a different memory layout. No 19D0 address, catalog slot or RAM address carries over to 20C0. What they share is the table format, the unit of the shift matrices, the checksum algorithm and the set of DS2 commands.
2. The gear selection logic is the same: 16 matrices, the unit is output shaft speed / 32, the matrix is chosen by the program number. Of 890 functions of 19D0, 763 have a counterpart in 20C0, some of them identical instruction for instruction.
3. Differences of the GS8.60.4 program (present in both BMW 15C0 and Alpina 20C0):
   1. torque converter lockup is allowed for gear codes 1–6 and is checked a second time, by turbine speed.
   2. with the converter locked an addition is added to the upshift threshold (`0x70B98`).
   3. there is an upshift request by engine speed.
   4. eight sets of shift automaton records instead of one.
4. Differences of the Alpina calibration (present in the Alpina 19D0 on GS8.60.0 too, absent in BMW 15C0): M at once in the left gate, turbine monitor threshold 7232 rpm instead of 6720, early lockup in M, early upshifts at part throttle, shorter shifts under load. Details in §10.
5. **"8604 is faster in stock form" is explained by the Alpina calibration, not by the unit** (§10). The 20C0 file `0520C06440` most often met as "stock GS8.60.4" is the Alpina B3S calibration. The factory BMW GS8.60.4 (`15C0`) equals the factory BMW GS8.60.0 (`19C0 KA20`) at the key places.
6. Documents 02–09 are written for the 19D0 addresses and carry over to 20C0 only through document 11. Patches and presets for both programs: documents 13 and 14. After any edit of 20C0 recompute the three checksums: `tools/gs860_crc.py fix`.

| calibration, checksum | `0x08000–0x0FFCD`, one zone, sum at `0xFFFE` | `0x70000–0x7FFCD`, zones `0x70000–0x71BC0` and `0x78000–0x7D858`, sum at `0x7FFFE` |
| program ROM constants | `0x10000–0x14FFF` | `0x08000–0x0FFFF` |

In 20C0 the ROM constants (`0x08000–0x0FFFF`: gear ratios, transition types, arbiter) are covered by the program checksum, not the calibration one. Document 01 and document 11 §1, §2.

## 3. Shift point matrices and gears

| | 19D0 | 20C0 |
|---|---|---|
| matrices | 16 tables 2D8 8×11 | 16 tables 2D8 8×11 at `0x7120E + k × 0x70`, k = 0…15 |
| axes | | equal to 19D0 in all 16 pairs, data equal in k9, k12, k13 |
| unit | output shaft speed / 32 (`0x24F5E lsr.w #5`) | the same (`0x20D36 lsr.w #5`) |
| speed function | `0x24E82` | `0x20C5A`, instruction for instruction |
| upshift | value `≥` matrix threshold (`0x24AC8`) | value `≥` matrix threshold plus the addition `[0xFFFF9143]` (`0x2061E`), the addition comes from `0x70B98` with the converter locked (`[0xFFFF91B3] = 2`, `0x20D8E`) |
| downshift | `0x24ADE` | `0x206A2`, the same |
| matrix choice by program | `0x24BA4` | `0x20768`, the same program to matrix table |
| matrix k7 | selected by program PC | never selected by the code: PC records refer to program 6 (matrix k2) |
| gear ratios | `0x12F9C[gear − 1]`, read in 24 places | `0x0E0D2[gear code]` = 3665, 3665, 1999, 1407, 1000, 742, 742, 4096, read by one function `0x41648` |
| gears 1–5 | 3.665 / 1.999 / 1.407 / 1.000 / 0.742 | the same numbers |
| gear code 6 | 1st with an extra shift element, the 1st-gear ratio (document 04 §2) | record 6 equals record 1 byte for byte, the ratio table holds 742 for code 6, purpose not established |
| gear records per program | | 6 (codes 1–6) |

The matrix roles are the same on 19D0 (document 01 §5) and 20C0 (proven on 06.10.2026 by code and a log, document 11 §5): D = k14 (P0) and k6 (P1), S = k11 (P2) and k15 (P3), M = k10 (PB), k8 (PD) at overheat. Document 11 §4.

## 4. Torque converter lockup, upper level

| | 19D0 | 20C0 |
|---|---|---|
| function | `0x29056` | `0x2547E` |
| mask of gears where lockup is allowed | `0x8978` = `0x003C`, gears 2–5 | `0x7096E` = `0x007E`, gear codes 1–6 |
| check by output shaft | group `0x897E`, thresholds `0x993A` 30×7 against n_out / 32 | `0x255F2`, group `0x70970`, thresholds `0x71996` 30×9 and `0x71AD0` 6×9 |
| check by turbine | none | `0x257C2`, thresholds `0x70BB2` against turbine / 32 `0xFFFF9145` |
| merging the two checks | none | ROM table `0x0AF1E` 3×3 |

The lower level (clutch automaton, PWM) of 20C0 is analysed in part: the engine-speed gate `0x4A766` (19D0 pair `0x32A8C`), fields f24 / f25 of root `0xFFFF9808` (1000 / 1500 or 820 / 1120 rpm by record). Document 03 and document 11 §6.

## 9. Identical instruction for instruction

Speed (`0x20C5A`), downshift (`0x206A2`), program arbitration (`0x1EC1C` and `0x1ED3C`, in 19D0 `0x23110` and `0x23230`), turbine monitor (`0x23086`), hold after a shift (`0x4A712`), `lookup − 128` (`0x5248E`). 20C0 addresses, the 19D0 counterparts are in document 11 §12. 763 of 890 19D0 functions were matched in total (25.09.2026).

## 10. Stock against stock: why GS8.60.4 feels "faster" (07.10.2026)

A common observation: a car with a stock GS8.60.4 shifts noticeably livelier than an E39 with GS8.60.0. Below are four factory calibrations, read from the images at the addresses of documents 01–05 and 11. BMW 15C0 is another build of the program; its addresses were mapped to 20C0 by the instruction sequences that read each cell (mostly 2 bytes lower: monitor `0x22FDE cmp.w $70BA6`, gate `0x70964`, addition `0x70B96`).

**Conclusions.**

1. The GS8.60.4 unit by itself is not faster. BMW 15C0 is almost equal to BMW 19C0 in the gate, the monitor, AGS and the D points, and its target times of the 2-3, 3-4 and 4-5 shifts under load are even longer.
2. The "fast" character is the Alpina calibration, and it is the same on GS8.60.0 and GS8.60.4: earlier upshifts at part throttle, earlier downshifts with the pedal floored without kick-down (2>1 up to 3636, 3>2 up to 4286 against 2815 and 3134 on BMW), earlier lockup in D (3rd from 2882 against 4052), M locks the converter from 2nd (2623) and hardly shifts by itself (on 20C0 the automatic 2>3 comes from 6525, 3>4 from 6799), M at once in the gate. Target shift times at full load against BMW 15C0 are shorter: 3-4 by 20–30 %, 2-3 by 13–26 %, 4-5 by 9–24 %, 1-2 by up to 10 %; against BMW 19C0 by 7–19 % at middle and high speed.
3. Only the GS8.60.4 program has the converter in 1st (mask `0x7E`) and the upshift addition with the converter locked. On GS8.60.0 the converter in 1st comes from the patch `tcc-first` with code (document 13 §1).
4. The engine and the body are not in this comparison: only the gearbox calibration was compared.
5. The Alpina character can be carried to BMW in part and without changing axes: gate, monitor, converter in M and S, full-throttle points (documents 13, 14). Shift time (hydraulics) is edited only where the table axes match (document 08 §3, document 09 §2).

## 11. GS8.60.4 22C0: BMW for an E46 with the 2.2 (08.10.2026)

The image of a received dump (512 KB, program label `B223K_0522C0`, the three sums are fine) is from an E46 with the 2.2 l engine and the 5HP19 box. It is the same family `B223K_05…` as the 20C0, but another build.

| | 20C0 (Alpina B3S, `6440`) | 22C0 (BMW, E46 2.2) |
|---|---|---|
| code `0x08000-0x6FFFF` | reference | 76 % of the bytes match, **another program** |
| shift-automaton records (`0x78000-0x7D85C`) | reference | same table addresses and shapes (876 of 978 headers match), own values |
| shift-point matrices | `0x7120E` + `0x70` × k | `0x7121C` + `0x70` × k (shift `+0x0E`); the first calibration block `0x70000-0x71C72` is shifted, the headers match in 5 of 52 |
| turbine monitor | `0x70BA8` = 7232 | `0x70BB4` = 6720 (BMW factory) |
| AGS (bit 5 of the flag) | off (`0x70D39` = `0x91`) | **on** (`0x70D47` = `0xFD`) |
| D, pedal 160, 1>2 / 2>3 / 3>4 / 4>5 (units) | 19 / 43 / 65 / 88 | 26 / 51 / 79 / 130 (later, at higher rpm) |
| S (k11) | almost equal to D | separate, differs from D |
| M (k10), row 0, upshifts 1>2 … 4>5 | 44 / 102 / 151 / 211 | 48 / 93 / 135 / 195 |

**What follows.**
- The XDF and the catalog of the 20C0 **fit the 22C0 only for the automaton records** (`0x78000` and up); the matrices, the gate constants, the monitor, the AGS and everything below `0x72000` are at other addresses. Do not open a 22C0 in the 20C0 XDF.
- `egs_patch.py` **refuses** such an image (it checks the SHA-256 of the 20C0 code). The 22C0 needs its own constant layout; the `shift-feel` tables in the records area are at the same addresses.
- On the 22C0 the AGS is on, so the statement "the AGS is off in the stock" is about the 20C0 file only.
- What box this is (from a 3 l car, as the owner of the image says) and how the 22C0 differs from the 15C0 cannot be seen in this dump.
