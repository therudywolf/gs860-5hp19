# 11 · GS8.60.4 (software 20C0, 512 KB): what is known and how it differs from GS8.60.0

Documents 01–10 describe the GS8.60.0 (software 19C0 / 19D0, 256 KB). This one is about the **GS8.60.4** with program **20C0** (512 KB image, program label `B223K_0520C0` at `0x6FF7C`, calibration label `B223K_0520C06440` at `0x7FFCE`). Everything below comes from two factory 20C0 images (a dump of an E46 and a factory file of the same calibration: they differ only inside the programming journal `0x4440–0x6089`, whose content and the unit serial are not reproduced here) and from a comparison with 19D0 by the method of document 10: capstone m68k, an own scan of address references, the pointer structures parsed from the image itself. Every instruction address in this document was re-checked against the image on 27.09.2026. Sections 5, 9, 10, 13 and 14 were extended on 30.09.2026: record field roles proven by the 20C0 code, all 20 record roots, the RAM of the execution module, the candidate `0x1AAFC` checked. 01.10.2026: the road-log data were removed from §5 (a third party's car log is not published under the repository rules), sixth gear was replaced by gear code 6 with what is proven about it (§4), the comparison with 19D0 moved to document 12. The calibration `0520C06440` is the Alpina B3S calibration; the factory BMW GS8.60.4 (`15C0 3Z16`) is another build of the program with addresses shifted mostly by 2 bytes, the calibrations are compared in document 12 §10. Patches and presets for 20C0: documents 13 and 14.

The confidence levels are those of `catalog/gs8604_20c0.json`: **proven** — a 20C0 instruction reads the address (the instruction address is given); **structure** — the same place in a structure as in 19D0 (catalog slot, record column, constant block) with the role proven there, the 20C0 read not examined separately; **shape** — a table header and axes or the pointer packing prove the size, the role is not established; **hypothesis** — not proven. What is not proven for 20C0 is called that.

## 2. Checksums (proven)

Three CRC-16/XMODEM sums (polynomial `0x1021`, initial value 0, table `0x3EE2` inside the image, equal to the 19D0 table at `0x3EDA`). The handler of DS2 command `0x0A` (`0x1392`) computes them with the routine `0x223C`; the right bound is excluded, the sum is stored big-endian.

| Region | Range | Stored at | Handler instructions |
|---|---|---|---|
| loader | `0x00000–0x043FF` | `0x5FFE` | `0x13FE cmpi.l #$4400`, `0x141A lea $5ffe` |
| program | `0x08000–0x6FF7B` | `0x6FFFE` | `0x143E move.l #$8000`, `0x1474 cmpi.l #$6ff7c`, `0x1490 lea $6fffe` |
| calibration | `0x70000–0x7FFCD` | `0x7FFFE` | `0x14B6 move.l #$70000`, `0x14EC cmpi.l #$7ffce`, `0x1508 lea $7fffe` |

The routine `0x223C` is called only by three `JSR`s of this handler (`0x13F6`, `0x146C`, `0x14E4`); there is no other call or pointer to it in the image: like 19x0, the unit checks the sums **only when a tester asks**, not at start-up. The result goes to bits 0–2 of `0xFFFF8ABF` and into the reply. Both factory images match on all three sums. Check and recompute: `python3 tools/gs860_crc.py check image.bin`, `gs860_crc.py fix edited.bin fixed.bin` (after any edit in TunerPro).

**Correction 08.10.2026.** The routine `0x223C` is the tester path only. In addition the unit runs a **background check**: the task `0x22BD2` (pointer in the task tables `0xA45E`, `0xA66A`, `0xA7EC`, period 100 ticks) continuously computes the CRC-16 of the three areas (loader, program, calibration) in chunks and compares them with the stored sums; a mismatch sets a bit in `[0xFFFF8BCB]` and the internal fault `0x0D` with the limp-home reaction (bit 0 of the mask word). A calibration whose sums were not recomputed (`tools/gs860_crc.py fix`) does not survive on the 20C0 code. One full pass takes minutes (measured in ticks, the tick length is not established).

The program region starts at `0x8000`, so **the ROM constants `0x08000–0x10000` (gear ratios, transition types, arbiter) belong to the program sum**, not to the calibration sum.

## 3. Calibration: zones, pointer catalog, objects

The table format is that of 19x0 (document 01 §2): `[u16 nx][u16 ny][X axis][Y axis][data]`, big-endian, axes strictly increasing. The scanner `egs_tables.py scan` finds **614 tables** in 20C0 (50 in the first zone, 564 in the second, 18,206 bytes); five scanner "tables" (`0x7104E`, `0x79A76`, `0x7A608`, `0x7A854`, `0x7B2FB`) are false — a record field points inside them — and are not in the catalog.

Pointer catalog `0x71BC2`: **43 slots** (the last at `0x71C6A`, then `0xFF`; earlier notes said "44" — recounted from the image). All 43 slots are read by code (the reading addresses are in the catalog). The 19D0 slots 0–5 (`0x8142`, `0x81A0`, `0x81B2`, `0x8226`, `0x824A`, `0x8EAC`) are not in the 20C0 catalog: the code takes the same tables directly (`0x7013A` at `0x25226`, `0x70196` at `0x1AAFC`, `0x701A8` at `0x1AB6C`, `0x70210` at `0x1173E`, `0x70236` at `0x1CDCC`, `0x70EF8` at `0x219E0`). 19D0 slots 6–41 = 20C0 slots 0–35, 42–47 = 37–42; slot 36 (`0x71C52 → 0x71AD0`) is new.

## 4. Shift-point matrices (proven)

16 tables 2D8 8×11 at `0x7120E + k × 0x70` (k = 0…15, data from `0x71225 + k × 0x70`), catalog slots 14–29. The Y axis is the gearbox pedal (`0xFFFF912B`), row 255 is kickdown. Columns 1–4 are the upshifts 1-2, 2-3, 3-4, 4-5, columns 5–8 the downshifts 2-1, 3-2, 4-3, 5-4: column and program come from the gear record `[down to][up to][down column][up column][down program][up program]` at `[0xFFFF8A2C + 4 × program] + 6 × (gear − 1)` (`0x205B4–0x205CE`); all 16 programs have the columns in this order. In 20C0 every program has six gear records (codes 1–6), see below for code 6.

**The unit is output shaft rpm / 32**, as in 19D0 (document 02 §3). The speed function `0x20C5A` matches 19D0 `0x24E82` instruction for instruction: filtered output shaft `0xFFFF8D18` (`0x20D2E`, filter weights `0x70FC4 / 0x70FC5` = 9 / 1), `lsr.w #5` (`0x20D36`), stored in `0xFFFF9138` (`0x20D38`). Channel-0 constant: 19D0 keeps K = 1,666,666 at `0x116C8`, 20C0 computes K = 60,000,000 / [`0x70302`] = 60,000,000 / 36 (`0x1E3D6–0x1E3EE`); the limits 33 / 8160 are at `0x70300` / `0x702FE` (19D0 `0x116CC` / `0x116CE`); channel 1 (turbine) has 18 pulses, `0x7096C`. Byte 2 of the `0B 03` frame is the same `0xFFFF9138` (`0x1438E`).

Comparison. Upshift `0x2061E`: the matrix threshold **plus `0xFFFF9143`** (`0x20660–0x20670`) against `0xFFFF9138` (`0x20688–0x20692`: shift when `9138 ≥ threshold + 9143`). The addition is set by the new function `0x20D8E`: with `[0xFFFF91B3] = 2` it is the byte `0x70B98[gear − 1]` = 4 / 2 / 2 / 5 / 0 / 4, otherwise 0. **`[0xFFFF91B3]` is the TCC clutch state** (0 open, 1 slip, 2 locked, analysed on 06.10.2026): `0x405F8` copies `[0xFFFF92D6]` = `[0xFFFF95EB]`, written by `0x4C4B2` (19D0 pair `0x33F66`) from the state of the clutch automaton. So with the converter locked the 1-2 upshift comes 469 turbine rpm later, 2-3 128, 3-4 90, 4-5 160. The addition is 16-bit, capped at 255. BMW 15C0 has the same addition (`0x70B96` = 3 / 2 / 2 / 5 / 0 / 3): it belongs to the GS8.60.4 program. Downshift `0x206A2` matches 19D0 `0x24ADE`: `0x206E4 cmp.b $ffff9138` with the threshold minus `0xFFFF9144`.

Matrix selection by program number (`0x20768`, branches onto the catalog slots) is the same as 19D0 `0x24BA4`:

| program | P0 | P1 | P2 | P3 | P4 | P5 | P6 | P7 | P8 | P9 | PA | PB | PC | PD | PE | PF |
|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|
| matrix k | 14 | 6 | 11 | 15 | 0 | 1 | 2 | 13 | 9 | 12 | 5 | 10 | 7 | 8 | 4 | 3 |

The gear records live in the calibration (list `0x08744`, bank 7 = `0x70000`): P0 `0x70FA0`, P1 `0x701CE`, P2 `0x70E72`, P3 `0x70FE4`, P4 `0x70000`, P5 `0x70024`, P6 `0x70048`, P7 `0x70F7C`, P8 `0x70A68`, P9 `0x70D96`, PA `0x700F2`, PB `0x70A32`, PC `0x702CC`, PD `0x702A8`, PE `0x700A0`, PF `0x7007C`. They show which matrices are reachable at all: the PC records in 20C0 name program 6 (matrix k2), not 12 as in 19D0, so **matrix k7 (`0x7151E`) is never selected by the shift code**. Program PA uses k14 in gears 1–4 and k5 in 5th, as in 19D0.

Gear ratios: `0x0E0D2` = 3665, 3665, 1999, 1407, 1000, 742, 742, 4096, indexed by gear code, read by one function `0x41648` (in 19D0 `0x12F9C[gear − 1]` is read directly in 24 places). Gears 1–5 are the same numbers: one matrix unit = 117.3 / 64.0 / 45.0 / 32.0 / 23.7 turbine rpm in 1st–5th.

**Gear code 6.** Its purpose in 20C0 is not established, it is not a sixth forward gear. Record 6 equals record 1 byte for byte in every program checked against the image (P0, P1, P2, PB, PC). No record shifts up into code 6: the up-to field of records 1–5 is 2, 3, 4, 5 and 0. Records 1 and 2 of programs PB and PC shift down into code 6 (down-to = 6), in P0, P1, P2 it is 1. The ratio table `0x0E0D2` holds 742 for code 6, the same as code 5. In 19D0 code 6 is 1st gear with an extra shift element and the 1st-gear ratio (document 04 §2). How 20C0 uses the 742 entry for code 6 has not been analysed.

Matrix data: the axes of all 16 pairs 19D0 / 20C0 are identical, the data match for k9, k12, k13. Example PB (k10), pedal 255, columns 1–8: 19D0 `49 95 137 200 41 86 129 189`, 20C0 `44 102 151 211 41 93 138 203`; the k10 upshifts do not depend on the pedal and with the 20C0 ratios give 5160 / 6525 / 6799 / 6752 turbine rpm (no slip). Minimum gear on manual downshifts `0x70B3C` (16 × 5, `0x1961C`): P0 `0 41 86 130 184`, PB `0 41 105 153 207`.

## 5. Matrix roles D, S, M (proven on 06.10.2026)

The roles are those of 19D0 (document 01 §5): **D = k14 (P0, AGS level 1) and k6 (P1, level 2), S = k11 (P2, level 3) and k15 (P3, level 4), M = k10 (PB, program code `0x0B`), k8 (PD, code `0x0D`) at overheat**. Proof by the 20C0 code:

- Gate `0x1EAEE` (19D0 pair `0x2300C`): the selector `[0xFFFF905D]` and the lever position `[0xFFFF91A8]` through the arrays `0x70DBC` / `0x70DD2` (19D0 reads the same data as `0x8D74 + 4` / `0x8D8E + 4`). In D the code is `0xFF`: program = AGS level through the map `0x09A42` = 0, 1, 2, 3 (as 19D0 `0x11864`). The lever in the left gate gives 8, and the code comes from `[0x70966]` (§7).
- The AGS points of the D branch are clamped between `[0x70890]` = 32 and `[0x7088E]` = 90, levels 1–2 by the ladder `0x70898` = 0 / 65 / 129 / 193, i.e. P0 and P1. The S branch between `[0x70891]` = 129 and `[0x7088F]` = 255, levels 3–4, i.e. P2 and P3 (`0x18E20–0x18E7A`). With `[0xFFFF918C]` = 2 the points stay at or above `[0x70892]` = 193 (level 4, P3).
- Arbitration `0x1EC1C` and permission `0x1ED3C` match 19D0 `0x23110` / `0x23230` instruction for instruction, pair table "code, priority" `0x09A46`. PD (code `0x0D`) replaces PB at overheat (`[0xFFFF907D]`, bit 7 of the byte `0x70D3A`).
- The upshift `0x2061E` compares `0xFFFF9138` with the matrix threshold plus the addition `0xFFFF9143` while the converter is locked (§4). Arbiter records 1, 2 and 25 (manual request) are set by `0x2042A`. The engine-rpm upshift request `0x105DE` (§7) works only when `[0xFFFF9066] ≤ 40`.
- The log of a run on 23.09.2026 of a car with 20C0 (a third party's car, not published here): in D byte 22 of the `0B 03` frame = program 0, in the gate `0xB2` (program B). The upshifts in the gate below the k10 thresholds, unexplained until 06.10.2026, are "+" taps: in M the matrix gives only the automatic upshift at the limiter and the automatic downshifts, the rest is the driver.

`egs_tables.py verify-shift` on 20C0 takes the roles from this section; the catalog and XDF carry the role in the matrix titles.

**The candidate `0x1AAFC` (30.09.2026) has nothing to do with the upshifts in the gate.** The 20C0 counterpart of 19D0 `0x81A0 / 0x81B2` is the pair `0x70196` and `0x701A8` (2D8 4×2, X = engine speed / 32 `[0xFFFF9140]`: 0 / 5312 / 5344 / 6208 rpm, Y = branch `[0xFFFF917F]`, Z = 15 / 15 / 30 / 30 and 15 × 8). All five reads (`0x1AAFC`, `0x1AC06`, `0x1ACE8`, `0x1AB6C`, `0x1AD7A`, call `0x19BD2`) compare the result with the **pedal rate** `[0xFFFF911E]`: `0x1FFCC–0x1FFE6` maps the pedal `[0xFFFF912A]` = `[0xFFFF911B]` (`0x1CDE6`) through the slot 1 table (`0x71064`) into `[0xFFFF906E]`, and `0x20000–0x20020` computes `|Δ[0xFFFF906E]| × 30 / Δt`. Exceeding it sets `[0xFFFF90B5] / [0xFFFF90B4] / [0xFFFF90B3]` and bit 7 of `[0xFFFF9061]` (`0x1AB24–0x1AB52`), no code tests bit 7 (the whole byte stands in the pointer lists `0xAD02–0xAE3E`, whose purpose is not analysed). With the pedal held at full throttle the pedal rate is zero and the threshold of 30 is never reached, so this block does not produce full-throttle upshifts.

## 6. TCC lockup, upper level (proven)

The 19D0 pair `0x29056` (document 03 §2) is the 20C0 function `0x2547E` with two checks.

- Gear mask `0x7096E` = `0x007E` (`0x25494 and.w`): lockup allowed for gear codes 1–6 (code 6 see §4, 19D0 `0x8978` = `0x003C`, 2nd–5th). The inhibit by an error with bit 8 is checked through `0x1532A` (`0x254B8`).
- **First check `0x255F2`**: group = byte `[0x70970 + 6 × program + gear − 1]` (`0x255F6–0x2561A`), 0 = no decision; thresholds `0x71996` 30×9 (slot 35, columns (group − 1) × 3 + 0…2) and `0x71AD0` 6×9 (slot 36, columns 30–35 = groups 11–12); compared with n_out/32 `0xFFFF9138`, hysteresis `0x70BB0` = 3. Rows are the gearbox pedal (0 / 5 / 46 / 59 / 72 / 224 / 230 / 240 / 255). Groups P0–P3: `11 4 1 2 3 0` (gears 1–6), PB: `0 5 8 9 10 11`.
- **Second check `0x257C2`, 20C0 only**: group `[0x709D0 + 6 × program + gear − 1]` (`0x257E4`), thresholds are the bytes `0x70BB2` (`0x25812`, index (group − 1) × 3 + 0…2) = 107 / 111 / 114 / 88 / 91 / 103 against **turbine / 32** `0xFFFF9145` (`0x2583A–0x2583E`), hysteresis `0x70BB1` = 3. Groups: P2, P3 — `0 2 2 2 2 0`, P4–P6 — `0 1 1 1 1 0`, PC, PD — `2 2 0 0 0 2`, the rest zero.
- The results of the two checks (0 / 1 / 2 each) are merged by the ROM table `0x0AF1E` 3×3 = `0 1 2 / 1 1 2 / 2 2 2` (`0x254FA`) into the request `0xFFFF91B4` (19D0 pair `0xFFFF91F9`). Hold by gear `0x70F20` = `0 6 6 6 6 0` (`0x25574–0x2557A` → `0xFFFF91D1`).

- **Converter lock-up in 1st from the factory (06.10.2026).** D and S use group 11 in 1st (`0x71AD0`, columns 30–32): threshold 202 (never) at pedal 0–224, and open 10, slip 11, lock 12 (n_out / 32) at 230 / 240 / 255, so near the floor the clutch locks from 1407 turbine rpm. Group 12 (columns 33–35) is used by no factory program; the patch `tcc-first` takes it (document 13 §1). BMW 15C0 has the mask `0x007E` too, but locks 1st only in the kick-down row, from 1994.

**Lower level, analysed in part (07.10.2026).** The clutch automaton keeps the state `[0xFFFF95E0]`; its record comes from root `9808`: `[0xFFFF958C]` = `9808.f00.e[[0xFFFF95E2]]` (`0x49C74–0x49C92`). Engine-speed gate `0x4A766` (19D0 pair `0x32A8C`, call `0x4A8A6`): in states other than 5 field f24 (+0x60, a table over ATF `[0xFFFF92BC]`) must be below the engine speed `[0xFFFF9282]`, otherwise the next state comes from the ROM table `0xE500[state]` (= 19D0 `0x12F40`, the opening path); from state 5 the automaton moves on only if field f25 (+0x64) is not above the engine speed. Factory: record 0 f24 = 1000, f25 = 1500 rpm, record 1 f24 = 820, f25 = 1120, flat over ATF. The other fields of `9808` and the record choice `0x495AE` are not analysed.

## 15. Results of 08.10.2026: clutch automaton, slip controller, faults, outputs

All read from the 20C0 code (instruction addresses in the owner's working reports), not checked on a live gearbox.

**Lower converter-clutch automaton.** State `[0xFFFF95E0]`: 0 reset for one cycle, 1 open, 2 pre-fill (PWM 2400 or 3000 on a scale of 8000, field `e.f05`), 3 approach to the target slip, 4 regulated slip (PI around `[0xFFFF952A]`), 5 controlled PWM decay, 6 PWM rise while locking, 7 locked (PWM `0x1F40` every cycle, `0x4C338`), 8 decay from locked to slip. The function `0x4A896` computes the candidate `[0xFFFF95E3]` every cycle from ROM tables (`0xE500`, `0xE50A`, `0xE4AC`, `0xE4C8`, `0xE4E4`, `0xE514`, `0xE530`, `0xE54C`); the state handlers in the dispatcher `0x4C4B2` accept it only under their own conditions. State 5 is reachable from 3 and 4, the PWM falls by `0x49B0C` (rate `f48` under power, `f55` on the overrun), it goes to 1 at PWM 0, the rpm threshold `f25` is above `f24` (hysteresis). Full lock-up (state 7) is not a flag: it needs the upper-level request `[0xFFFF92CB]` = 2, the ATF class, no `nAb` inhibit on the overrun and `[0xFFFF9514]` below `f60` for `f69`. `[0xFFFF95E2]` = 1 is power (load `[0xFFFF92C2]` above the curve of `nMot32`, `0x4130C`), 0 is overrun. The clutch PWM `[0xFFFF9536]` leaves through `[0xFFFF928E]` to driver channel 2 (`0x47F72`); it is the output EDS4 (`0xFFFFFF34`, fault `0x09`, P2761).

**Slip controller and adaptation.** `[0xFFFF974B]` exists in 19D0 only. In 20C0 the pair is `[0xFFFF93CF]`: 1 = the controller drives the on-coming clutch, 0 = the off-going one (`0x418EA`). Kind 2 (downshift without throttle) and kind 1 drive the on-coming one, kind 3 and kind 0 the off-going one; for kind 0 the controller idles (mode 0, phase 11 at once). The channel and the element come from the tables `0xE388`, `0xE38E`, `0xE398`, `0xE39E` (channel) and `0xE358`, `0xE35E`, `0xE368`, `0xE36E` (element) by the shift type (`0x47854`). The adaptation is two automata, both write to the non-volatile data through `0x1DFCA` with the sum `[0xFFFF99E0]`: downshifts (set `980C`, cells `9A0E[22]`, `9A3A[22]`, kind 3 only, types 4>3, 3>2, 4>2, 5>4, 5>3) and upshifts (set `9814`, cells `9AEA[16]`, `9B0A[16]`, step ±2, limits `f15` / `f16`, correction into the on-coming pressure `[0xFFFF936E]`).

**Faults and limp mode.** DS2 table `0x707A0`: the internal fault `0x25` (turbine monitor, threshold `0x70BA8` = 7232) gives the DS2 code `0x21` (P0716 overspeed / P0715 no signal); the code `0x95` belongs to the fault `0x24` (wheel speeds from CAN invalid, no limp mode). Limp mode is bit 0 of the mask word `[0xFFFF8F34]`: the output stage is switched off (`PORTC` bit 4 := 1, `0x14E94`), 4th gear commanded, no re-enable until the self-test at start. Bit 0 is set in the masks of 17 faults: `03, 06-09, 0D, 1B, 1C, 1E, 1F, 20, 22, 25, 27, 29, 2D, 2E`. `[0x70CB8]` = 2 switches off the logging of all faults, protective ones included. The background CRC check (`0x22BD2`) raises the fault `0x0D`, see §2. The voltage window of the self-test is 9-16 V (`0x70F52` / `0x70F56`): without it the automaton does not start and the gear stays 4th.

**Outputs.** MV1 / MV2 / MV3 = `[0xFFFF90C1]` / `[90C3]` / `[90C5]` on `PORTC` (`0xFFFFFA41`) bits 0 / 1 / 2, active 0; EDS1-EDS4 = `[0xFFFF8C38]`, `[8C3C]`, `[8C40]`, `[8C44]` on TPU channels 0-3; EDS5 = `[0xFFFF8C48]` at `0xFFFFF43C`. The common enable bit of the stage: `PORTC` bit 4. Feedback: for the EDS in `[0xFFFF8F38…8F40]`, for the MV in the ADC `[0xFFFF9002…9010]`.

**The AGS is inactive in the factory 20C0.** The function `0x19084` is called from `0x18676` only when bit 5 of the byte `0x70D39` is set; it is 0 in the Alpina B3S 20C0, E46 and BMW 15C0 images. The pedal thresholds of the AGS (slots 3-12, the Y axis is output shaft rpm / 32, not the pedal), the score matrices `0x708A8` / `0x708B8` and the constants `0x70192` / `0x70193`, `0x7089C`, `0x708C8` / `0x708C9`, `0x70EDA` have no effect in the stock. In 19D0 the flag is set (`0x8CE7` = `0xFD`).

**The hydraulics do not depend on the program D / S / M.** The record selector `0x41842` reads the shift type and kind, the kind comes from the load class (`0xE0E2[class × 4 + direction]`), the variant `[0xFFFF93C0]` from the shift state. Hence the patch `shift-feel` (document 13 §10): the hardness follows the load, not the program.

**RAM cells (meaning by code).** `[0xFFFF91EC]` AGS score increment per pedal-rate step (`0x708EA`); `[0xFFFF9117]` lower bound of the step score (`0x70898`); `[0xFFFF918C]` = 2 a request for the dynamic mode from CAN (AGS score at least 193, sub-mode `[0xFFFF91A8]` = 1, the gate takes `0x70967`; the source, button or DME, is not proven); `[0xFFFF914B]` index of a flag from `0x7100A`; `[0xFFFF99F4]`, `[99F8]`, `[99FC]` three 24-bit time counters in lever position 4 by mode, step 977 ticks, written to non-volatile memory; the table `0x0AF1E` is the maximum of two converter-lock requests (`[0xFFFF91AF]`, `[91B1]`) into `[0xFFFF91B0]`.

**Not established.** The pressure and current units; which physical clutch each element and channel number is; who starts the erasing of the adaptations (`[0xFFFF96B2]` = `0x10`) and whether they survive power-off; the tick length (so the times are in ticks, not ms); the meaning of `[0xFFFF94FE]` / `[94FF]`, the physical meaning of the total torque `[0xFFFF92EE]`, the meaning of the states `[0xFFFF945E]`; the places where the faults `01, 0A, 0B, 0E, 2C, 32-35` are set.

## 14. Tools

- `python3 tools/egs_tables.py info | scan | shift | programs | dump | diff | verify-shift image.bin` — the layout is chosen by the file size (512 KB = 20C0). `info` prints the code hash `0x08000–0x70000` (reference `28d92179…`), the labels, the 614 tables, the three sums. `shift --turbine` shows the 16 matrices in turbine rpm; `verify-shift` on 20C0 takes the D / S / M roles from the code (§5) and counts the upshift threshold with the addition `0x70B98` while the converter is locked.
- `python3 tools/egs_patch.py list | show | apply | preset | recipe` — the patches of document 13 and the presets of document 14 for 20C0 and 19x0.
- `python3 tools/gs860_crc.py check | fix` — the three 20C0 sums (layout by file size).
- `python3 tools/make_xdf.py check catalog/gs8604_20c0.json`, `make_xdf.py build catalog/gs8604_20c0.json xdf/GS8604_20C0_Full512K.xdf --en xdf/GS8604_20C0_Full512K_EN.xdf` — the XDF from the catalog, Russian and English (fields `title_en`, `description_en`, `units_en`, `categories_en`); `check` rejects overlaps, duplicates, empty units and addresses outside the image.
- The 20C0 catalog is generated from a 20C0 image by the WOLF4X project generator (all 20 record roots, roles with instruction addresses) and is never edited by hand. Its field roles are only those found in the 20C0 code: the read of the field, the writes of the axis variables, the path to an output.
- The recipes `recipes/gs8604_20c0_*.json` (document 14) are built for 20C0. The older recipes v18–v20 and the addresses of documents 02–09 **do not apply** to 20C0: other addresses, other structures. Only the method and the units are shared with 19D0.
